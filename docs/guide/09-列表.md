# 9. 列表

## `each`：随数据增删的子元素

```rust
pub fn todo_view(store: Store) -> Element {
    let draft = signal(String::new());
    let add = move || {
        store.add(&draft.get_untracked());
        draft.set(String::new());
    };
    column()
        .gap(10)
        .width(480)
        .child(
            row()
                .gap(8)
                .child(
                    text_field(draft)
                        .placeholder("要做什么？按回车添加")
                        .grow(1)
                        .on_submit(move |_| add()),
                )
                .child(button("添加").on_click(add)),
        )
        .child(column().gap(6).each(move || store.todos.get(), |todo| todo.id, move |todo| todo_row(todo, store)))
        .child_when(move || store.todos.with(Vec::is_empty), || text("这里还没有事项").color(MUTED))
        .child(text(move || format!("{} 项未完成", store.remaining())).font_size(13).color(MUTED))
}

fn todo_row(todo: Todo, store: Store) -> Element {
    let Todo { id, title, done } = todo;
    row()
        .gap(10)
        .align(Align::Center)
        .padding_x(12)
        .padding_y(8)
        .radius(6)
        .background(SURFACE)
        .border(1, LINE)
        .clip(true) // 收起高度时内容不溢出
        .exit(Property::Opacity, 0.0) // 删除时淡出
        .exit(Property::Height, 0.0) // 同时高度收为 0，下面的行平滑补上
        .exit(Property::Padding, 0.0)
        .child(checkbox(done).accessibility_name(title.clone())) // 只有方框：给辅助技术起个名字
        .child(text(title).grow(1).strikethrough(done).color(move || if done.get() { MUTED } else { TEXT }))
        .child(button("删除").on_click(move || store.remove(id)))
}
```

- `.each(数据, key, 视图)` **按 key 增量更新**：key 不变的项保留节点和状态，新 key 才构建，消失的 key 连同它的绑定和信号一起释放，顺序变化只是重排。
- `.child_when(条件, 视图)` 是 0 或 1 项的特例。
- 静态的 `.child(..)` 和动态的 `.each(..)` / `.child_when(..)` 可以混用，按声明顺序排列。
- `.exit(..)` 声明退场动画：曲线用这个属性 `.transition(..)` 声明的，没有就用 200ms 的 ease-out。高度、内边距收为 0 时下面的行平滑补上；配合 `.clip(true)`，收起时内容不会溢出。退场中的元素不再响应指针。

## 虚拟列表

十万行数据也只挂载看得见的几十行，滚动时按 key 挂载新行、卸载离开的行：

```rust
pub fn messages() -> Element {
    let ids = signal((0..100_000u32).collect::<Vec<_>>());
    virtual_list(ids, |&id| id, 56, |id: u32| {
        row()
            .padding_x(16)
            .gap(12)
            .align(Align::Center)
            .child(rect().size(32, 32).radius(16).background(ACCENT_SOFT)) // 头像的位置
            .child(text(format!("第 {id} 条消息")))
    })
    .height(400) // 列表本身是滚动视口：要给高度（或 grow）
}

pub fn variable_rows() -> Element {
    let ids = signal((0..10_000u32).collect::<Vec<_>>());
    let height = |&id: &u32| if id.is_multiple_of(10) { 120.0 } else { 48.0 }; // 每一项的高度
    virtual_list(ids, |&id| id, height, |id: u32| {
        let big = id.is_multiple_of(10);
        column().padding(12).child(text(if big { format!("第 {id} 组") } else { format!("第 {id} 行") }).font_size(if big { 22 } else { 14 }))
    })
    .grow(1)
}
```

- 数据可以是 `Signal<Vec<T>>`、`Memo<Vec<T>>`（按引用读，滚动时不复制整个列表），或者返回 `Vec<T>` 的闭包（结果缓存，依赖变了才重新调用）。
- 行高是固定值，或者按项给出（数据变化时算一遍前缀和）。行元素没指定高度时撑满这一行。
- 返回的是一个竖向滚动视口，可以接着设大小、背景、`.scroll_handle(..)`。
- 表格就是一行表头加一个虚拟列表，每行是一个横排，各列给同样的宽度。

行高事先算不出来（聊天记录、动态：文字长短不一、按宽度换行）时，行高给 `measured()`：

```rust
pub fn chat_log() -> Element {
    let messages = signal((0..100_000u32).map(|id| (id, "长一点的消息会换行。".repeat(1 + id as usize % 5))).collect::<Vec<_>>());
    let list = ScrollHandle::new();
    column()
        .height(480)
        .gap(8)
        .child(
            row()
                .gap(8)
                .child(button("第 5 万条").on_click(move || list.scroll_to_index(50_000))) // 没量过的地方也停得准
                .child(button("最新").on_click(move || list.scroll_to_index(messages.with(Vec::len) - 1))), // 之后一直贴着底
        )
        .child(
            virtual_list(messages, |&(id, _)| id, measured(), |(id, body): (u32, String)| {
                column().padding_x(16).padding_y(8).gap(4).child(text(format!("用户 {}", id % 97)).font_size(12)).child(text(body))
            })
            .grow(1) // 行高由内容决定：挂载后量出来
            .scroll_handle(list),
        )
}
```

- 每行按自然高度排，挂载后量出实际高度（按 key 记住，滚回来不用再量）；没挂载过的行按量过的平均高度估计，`measured().estimate(72)` 给一个固定的估计。
- **看到的内容不跳**：视口顶上那一行在屏幕上不动。量出来的高度和估计的不一样（往上滚进没量过的行）、前面插入或删掉几项时，偏移跟着挪，触控板、惯性、滚轮照常接着走。
- 行高会变（窗口变窄后换行变多、展开收起）时每次布局后重新量，下面的行跟着挪。
- `scroll_to_index(i)` / `jump_to_index(i)` 把第 i 行滚到顶上（固定行高的列表、普通视口也能用）。目标在很远的、没量过的地方时，滚到附近量出来以后目标跟着修正，停下时正好在那一行；之后行高再变也保持在那里，直到用户自己滚动——所以滚到最后一项就一直贴着底。
- 只有新的行进来的那一帧布局和量，其余的帧只平移合成层。

## 坑

- **每一项的视图只在它第一次出现时构建一次**。同一个 key 的数据里某个普通字段变了，界面不会跟着变：会变的字段放进信号（像 `Todo::done`）。
- key 要稳定、唯一：用 id，不要用下标（插入一项会让后面所有行都换 key、重建）。
- `each` 的数据闭包每次依赖变化都会被调用并返回整个 `Vec`；很长的列表用虚拟列表，或者先用 `memo` 算好。
- 虚拟列表的行离开视口就卸载，行里的状态（比如展开、输入了一半的文字）要放进数据。
- `measured()` 的列表量的是行的自然高度：行元素不要用 `grow` 或者百分比高度去撑满什么（没有可撑满的高度）。
- 窗口变宽变窄以后，挂载着的行马上重新量；没挂载的行还记着按旧宽度量的高度，滚到时再修正（看到的内容不跳，只是滚动条长度会再变一点）。
- 内容很高（几百万像素以上）时偏移的精度有限（`f32`）：一千万像素左右滚到第几行可能差 1 像素。
