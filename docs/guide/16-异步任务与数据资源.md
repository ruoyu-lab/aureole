# 16. 异步任务与数据资源

本章的导入：

```rust
use aureole::prelude::*;
```

## 三种任务

```rust
/// 模拟的网络请求：在后台线程上运行
async fn fetch_user(id: u32) -> Result<String, String> {
    aureole::sleep(ms(300)).await;
    if id == 0 { Err("没有这个用户".into()) } else { Ok(format!("用户 {id}")) }
}

fn count_primes(limit: u32) -> usize {
    (2..limit).filter(|n| (2..).take_while(|d| d * d <= *n).all(|d| n % d != 0)).count()
}

pub fn background() -> Element {
    let name = signal(String::from("加载中…"));
    let primes = signal(None::<usize>);
    aureole::spawn(fetch_user(7)).then(move |user| name.set(user.unwrap_or_default())); // 后台 future，结果交回主线程
    aureole::spawn_blocking(|| count_primes(200_000)).then(move |n| primes.set(Some(n))); // 阻塞的计算放到阻塞线程池
    column().gap(8).child(text(move || name.get())).child(text(move || match primes.get() {
        Some(n) => format!("20 万以内有 {n} 个质数"),
        None => "计算中…".into(),
    }))
}

pub fn local_flow() -> Element {
    let status = signal(String::from("还没开始"));
    column().gap(8).align(Align::Start).child(text(move || status.get())).child(button("开始").on_click(move || {
        aureole::spawn_local(async move {
            status.set("请求中…".into());
            let user = aureole::spawn(fetch_user(1)).await; // 等后台任务，界面照常
            status.set(format!("拿到 {user:?}，再等一秒"));
            aureole::sleep(secs(1)).await;
            status.set("完成".into());
        })
    }))
}
```

| | 在哪运行 | 用来 |
|---|---|---|
| `aureole::spawn(future)` | 后台线程池 | 不阻塞的 future（网络请求） |
| `aureole::spawn_blocking(闭包)` | 阻塞线程池 | 大量计算、同步读写文件 |
| `aureole::spawn_local(future)` | 主线程 | 一串异步步骤：能读写信号，`.await` 后台任务、文件对话框、`aureole::sleep` |

`task.then(f)` 在主线程等结果再调用 `f`，`f` 里可以直接写信号。后台任务也能 `.await`（在 `spawn_local` 或另一个后台任务里）。框架自带执行器（`PoolSpawner`），没有任务时没有线程在工作；要换成别的运行时见下面和第 [26](26-插件和扩展点.md) 章。第三方库的回调线程上要回到主线程，用 `aureole::main_thread_sender()`（第 [26](26-插件和扩展点.md) 章）。

**线程规则靠类型保证**：信号、元素这些句柄不是 `Send`，带不进 `spawn` / `spawn_blocking`（编译不过）。后台只处理数据，结果必须是 `Send`，回到主线程再写信号。

**任务归创建时的作用域所有**：元素卸载、窗口关闭、副作用重新执行时自动取消，后台的 future 被丢弃，结果不再交回来。丢掉 `Task` 句柄**不会**取消任务，要取消用 `.cancel()`，要跟着一个值走用 `.guard()`（第 [26](26-插件和扩展点.md) 章）。

## 数据资源

`resource(依赖, 请求)`：依赖变了自动重新请求，加载中、数据、错误都是响应式的：

```rust
pub fn user_lookup() -> Element {
    let id = signal(1u32);
    let user = resource(move || id.get(), fetch_user); // id 变了自动重新请求，过期的结果丢掉
    column()
        .gap(8)
        .align(Align::Start)
        .child(
            text(move || match (user.get(), user.error()) {
                (_, Some(error)) => format!("出错了：{error}"),
                (Some(name), _) => name,
                (None, _) => "加载中…".into(),
            })
            .opacity(move || if user.is_loading() { 0.5 } else { 1.0 }), // 加载新数据期间旧数据还在，变淡就好
        )
        .child(
            row()
                .gap(8)
                .child(button("下一个").on_click(move || id.update(|i| *i += 1)))
                .child(button("不存在的").on_click(move || id.set(0)))
                .child(button("刷新").on_click(move || user.refetch())),
        )
}
```

- 请求返回 `Result<T, E>` 的 future（在后台线程池上运行）。依赖再变时，**上一次没完成的请求被取消，晚到的旧结果不会覆盖新结果**。
- `get()` 是最近一次成功的数据，加载新数据期间不清空（界面不闪）；`is_loading()`、`error()`；`refetch()` 重新加载，`set(..)` 直接改数据（乐观更新）。

## 防抖：边打边搜

```rust
const CITIES: [&str; 8] = ["北京", "上海", "广州", "深圳", "杭州", "南京", "成都", "西安"];

pub fn search() -> Element {
    let query = signal(String::new());
    let settled = aureole::debounced(move || query.get(), ms(250)); // 停止输入 250ms 后才变
    let hits = resource(move || settled.get(), |q: String| async move {
        aureole::sleep(ms(200)).await;
        Ok::<_, String>(CITIES.iter().filter(|c| !q.is_empty() && c.contains(q.as_str())).map(|c| c.to_string()).collect::<Vec<_>>())
    });
    column()
        .gap(8)
        .width(280)
        .child(text_field(query).placeholder("搜索城市").full_width(true))
        .child(column().gap(4).each(move || hits.get().unwrap_or_default(), String::clone, text))
}
```

`aureole::debounced(源, 延迟)` 返回一个信号，源的值停止变化一段时间后才跟着变；和 `resource` 组合，打字期间不发请求。

## 和 tokio 一起用：reqwest、sqlx……

框架自带的执行器没有 tokio 的反应器和计时器，reqwest、sqlx、tonic 这些库放进 `aureole::spawn` 会报"there is no reactor running"。打开 `tokio` 特性（默认关，不用就不编译 tokio）。有两种用法：

- **只有几处要 tokio**：用 `aureole::spawn_tokio`、`aureole::resource_tokio`，别的任务留在框架自己的线程池上（下面的例子）。
- **整个应用都用 tokio**：装插件 `App::new(app).plugin(aureole::TokioPlugin::default())`，或者 `App::spawner(aureole::TokioSpawner::default())`，之后普通的 `spawn`、`spawn_blocking`、`resource` 都在 tokio 上跑。

打开特性本身不改变 `spawn` 的执行位置，换不换是应用明确的选择。

```toml
[dependencies]
aureole = { version = "0.0.1-beta.1", features = ["tokio"] }
```

`spawn_tokio` 和 `resource_tokio` 把 future 放到 tokio 运行时上跑，返回的还是 `Task`、`Resource`：`then`、`.await`、取消、`is_loading()` 的写法都一样。

```rust
/// 代替 reqwest 的客户端：只能在 tokio 运行时里用（tokio 的计时器模拟网络延迟）。
/// 真实应用里是 `reqwest::get(url).await?.text().await` 这样的调用
async fn get_text(url: String) -> Result<String, String> {
    tokio::time::sleep(ms(200)).await;
    if url.ends_with("/0") { Err("404：没有这个城市".into()) } else { Ok(format!("{url}：晴，24°C")) }
}

pub fn weather() -> Element {
    let city = signal(1u32);
    let ping = signal(String::new());
    // 请求在 tokio 运行时上跑；city 变了自动重新请求，上一次的请求被 abort
    let report = aureole::resource_tokio(move || city.get(), |id| get_text(format!("https://api.example.com/weather/{id}")));
    column()
        .gap(8)
        .align(Align::Start)
        .child(text(move || match (report.get(), report.error()) {
            (_, Some(error)) => format!("出错了：{error}"),
            (Some(text), _) => text,
            (None, _) => "加载中…".into(),
        }))
        .child(
            row()
                .gap(8)
                .child(button("下一个城市").on_click(move || city.update(|c| *c += 1)))
                .child(button("测一下网络").on_click(move || {
                    // 一次性的请求：结果在主线程交给闭包
                    aureole::spawn_tokio(get_text("https://api.example.com/ping".into())).then(move |r| ping.set(r.unwrap_or_else(|e| e)));
                })),
        )
        .child(text(move || ping.get()))
}
```

- 运行时第一次用时创建（多线程，工作线程数是核数、限制在 2 到 8，计时器和网络都开着），空闲时不占 CPU。
- 应用已经有自己的运行时，在第一次用之前交给框架；之后 `aureole::tokio_handle()` 就是它：

```rust
/// 应用已经有自己的 tokio 运行时：在第一次用之前交给框架
pub fn main() {
    let runtime = tokio::runtime::Runtime::new().expect("创建 tokio 运行时失败");
    aureole::set_tokio_runtime(runtime.handle().clone()).expect("要在第一次 spawn_tokio 之前设置");
    App::new(weather).title("天气").run(); // runtime 一直活到事件循环结束
}
```

- 用不着 `#[tokio::main]`：`App::run` 占着主线程跑事件循环、不返回，future 在运行时的工作线程上跑；像上面这样自己建运行时更清楚。用了也行：在它的 `main` 里第一次用时直接用那个运行时，不另建。单线程的运行时（`current_thread`）没有线程推进它，`set_tokio_runtime` 会退回。
- `spawn_tokio` 里也能 `tokio::spawn` 更多任务，但只有 `spawn_tokio` 返回的那一个会把结果交回主线程、随作用域取消。
- 不需要 tokio 的后台工作照旧用 `aureole::spawn`（框架自己的线程池，没有任务时没有线程在工作）。

## 坑

- 界面上的延时、防抖、轮询用 `aureole::after` / `aureole::every` / `aureole::debounced`（测试工具里按虚拟时间走）；`aureole::sleep` 只在 async 代码里用（和定时器同一个时钟：应用里是真实时间，测试工具里跟着虚拟时间走）。
- 后台任务 panic 时线程池照常工作，`then` 的闭包不调用，`.await` 它的一方跟着 panic；资源只结束加载状态。`spawn_tokio` 的任务也一样。
- `tokio::time::sleep`、`tokio::net` 只能在 `spawn_tokio` 里用；在 `aureole::spawn` 里用会 panic（没有 tokio 的运行时）。`aureole::sleep` 两边都能用。
- 在别的作用域里等一个已被取消的任务会一直等下去。
- 任务没有进度汇报（流式结果）；要显示进度，在 `spawn_local` 里分几步做。
