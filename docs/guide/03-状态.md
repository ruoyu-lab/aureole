# 3. 状态：信号、派生值、副作用

本章的导入：

```rust
use std::cell::Cell;
use std::rc::Rc;

use aureole::Scope;
use aureole::prelude::*;
```

## 信号、派生值、副作用

```rust
pub fn basics() {
    let count = signal(1);
    let double = memo(move || count.get() * 2); // 派生值：用到时才算，结果缓存
    let log = Effect::new(move || println!("double = {}", double.get())); // 立即执行一次，之后依赖变了再执行
    count.set(2); // 打印 double = 4
    count.update(|n| *n += 1); // 原地修改，打印 double = 6
    assert_eq!(double.get_untracked(), 6);

    let name = signal(String::from("林小梨"));
    let chars = name.with(|s| s.chars().count()); // 借用着读，不克隆
    assert_eq!(chars, 3);
    assert!(!count.set_if_changed(3)); // 值没变：不写、不通知
    log.dispose(); // 手动停掉（一般交给作用域）
}
```

| | 用途 |
|---|---|
| `signal(v)` | 可读写的状态。`get()` 读并订阅，`get_untracked()` 读不订阅，`with(\|v\| ..)` 借用读，`set(v)` / `update(\|v\| ..)` 写，`set_if_changed(v)` 不同时才写 |
| `memo(f)` | 派生值：第一次读时才算，之后依赖变了、又被读到时才重算；结果和上次相等（`PartialEq`）时下游什么都不做 |
| `Effect::new(f)` | 副作用：立即执行一次，读过的信号变了就重新执行。界面上的每个绑定都是一个副作用 |

句柄（`Signal`、`Memo`、`Effect`）都是 `Copy` 的，闭包随便捕获，不会和借用检查器打架。值存在当前线程的运行时里，句柄不能跨线程。

## 批量更新、不订阅地读

```rust
pub fn batching() {
    let first = signal(String::from("张"));
    let last = signal(String::from("三"));
    let runs = Rc::new(Cell::new(0));
    let counter = runs.clone();
    Effect::new(move || {
        let _full = format!("{}{}", first.get(), last.get());
        counter.set(counter.get() + 1);
    });
    batch(|| {
        first.set("李".into());
        last.set("四".into());
    });
    assert_eq!(runs.get(), 2); // 创建时一次，批量更新结束时一次（不是三次）
}

pub fn read_untracked() {
    let query = signal(String::from("杭州"));
    let page = signal(1);
    Effect::new(move || {
        let q = query.get(); // 订阅：query 变了重新执行
        let p = page.get_untracked(); // 只读当前值，page 变了不重新执行
        let size = untracked(|| page.get() * 20); // 一段代码里都不订阅
        println!("搜索 {q}，第 {p} 页，每页 {size}");
    });
    page.set(2); // 不打印
    query.set("上海".into()); // 打印"搜索 上海，第 2 页……"
}
```

**处理器、定时器、异步任务交回的结果本来就在批量更新里执行**，里面改几个信号，界面只更新一次，不用自己包 `batch`。

## 作用域和资源释放

每个信号、副作用都归创建它时的**作用域**所有，作用域释放时一起释放：

```rust
pub fn scopes() {
    let before = aureole::live_node_count();
    let scope = Scope::new();
    scope.run(|| {
        let n = signal(0);
        Effect::new(move || println!("n = {}", n.get()));
        aureole::on_cleanup(|| println!("作用域释放了"));
    });
    scope.dispose(); // 连同里面的信号、副作用一起释放，并调用 on_cleanup 的闭包
    assert_eq!(aureole::live_node_count(), before); // 没有泄漏
}
```

框架替你管理作用域，平时不用手动建：

- 每个窗口一个作用域，关窗口时释放。构建视图时创建的信号归它。
- `each` 列表里的每一项、`child_when` 的内容、浮层的内容各有自己的作用域，被移除、关闭时释放（连同里面的绑定、信号、定时器、异步任务、快捷键）。
- 处理器在**创建元素时的作用域**里执行：处理器里新建的信号归元素所在的作用域，元素卸载时一起释放。
- 副作用重新执行前，会先释放上一次执行时创建的东西。
- `aureole::on_cleanup(f)`：当前作用域释放（或副作用重新执行）时调用 `f`，用来释放作用域之外的资源。在所有作用域之外登记的、线程结束时作用域还没释放的不调用。

## 组织应用状态

把状态放进一个由信号组成的结构体，整个结构体也是 `Copy` 的，在视图函数之间随便传：

```rust
/// 一条待办：会变的字段放进信号
#[derive(Clone, PartialEq)]
pub struct Todo {
    pub id: u64,
    pub title: String,
    pub done: Signal<bool>,
}

/// 应用状态：全是 `Copy` 的信号句柄，视图函数之间随便传
#[derive(Clone, Copy)]
pub struct Store {
    pub todos: Signal<Vec<Todo>>,
    next_id: Signal<u64>,
}

impl Default for Store {
    fn default() -> Self {
        Self { todos: signal(Vec::new()), next_id: signal(1) }
    }
}

impl Store {
    pub fn add(self, title: &str) {
        let title = title.trim();
        if title.is_empty() {
            return;
        }
        let id = self.next_id.get_untracked();
        self.next_id.set(id + 1);
        let todo = Todo { id, title: title.to_owned(), done: signal(false) };
        self.todos.update(|todos| todos.push(todo));
    }

    /// 删掉数据，同时释放随它创建的信号（等界面上的这一行卸载完才真正释放）
    pub fn remove(self, id: u64) {
        let mut removed = Vec::new();
        self.todos.update(|todos| removed.extend(todos.extract_if(.., |t| t.id == id)));
        for todo in removed {
            todo.done.dispose();
        }
    }

    pub fn remaining(self) -> usize {
        self.todos.with(|todos| todos.iter().filter(|t| !t.done.get()).count())
    }
}

pub fn shared_main() {
    let store = Store::default(); // 在 App::new 之前创建：不归任何窗口，活到程序结束
    App::new(move || crate::lists::todo_view(store)).title("待办").run();
}
```

`todo_view` 是第 [9](09-列表.md) 章的待办清单界面。

## 坑

- **读已释放的信号会 panic**（说明逻辑有错），写已释放的信号什么都不做（迟到的异步结果很常见）。典型场景：在浮层、对话框、列表项里创建的信号，浮层关掉、那一项被删掉后就释放了；要比它们活得久的数据，在外面（比如 `Store` 里）创建。
- 随数据创建的信号（比如每条待办的 `done`）不归界面所有，删数据时用 `dispose()` 释放，否则会一直留着。在处理器里调用时，等这一轮更新跑完才真正释放，所以依赖它的那一行会先卸载，不会读到已释放的信号。
- `update(|v| ..)` 的闭包里不能再读写同一个信号（会 panic，提示改用 `set`）；`with(|v| ..)` 的闭包里 `set` 同一个信号可以，写入立即生效，这次读看到的还是读开始时的值。
- 在副作用、派生值里读到的信号都会被订阅。只想读一下当前值时用 `get_untracked()`，否则这个副作用会在不该重跑的时候重跑。
- 要在多个窗口之间共享、或者活到程序结束的状态，在 `main` 里、`App::new` 之前创建。
- 绑定、派生值 panic 以后运行时的状态复位，输入修好时出错的绑定自己恢复；panic 照样往外传，接不接住由应用决定。副作用之间互相写、停不下来时，一次更新最多 100 轮。
