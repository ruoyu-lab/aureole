# 19. 无障碍

每个窗口都接了读屏软件（macOS 的 VoiceOver 等）。辅助技术第一次来要无障碍树时才开始工作，之前没有开销。**大多数情况不用手动标注**，角色按元素推断：文字是标签，输入框是文本框，有 `on_click` 的是按钮，滚动视口是滚动区域，虚拟列表是列表（每行知道自己是第几行、一共几行），模态浮层是对话框，提示是提示，有数值的是滑块或进度条；基础控件声明好了角色、状态和数值（第 [14](14-基础控件.md) 章）。焦点、Tab 顺序、键盘操作和辅助技术双向同步。

## 什么时候需要手动标注

本章的导入：

```rust
use aureole::RangeValue;
use aureole::prelude::*;
```

```rust
pub fn labels() -> Element {
    let (name, city, subscribe) = (signal(String::new()), signal(String::new()), signal(false));
    let city_focus = FocusHandle::new();
    let trash = VectorPath::svg("M5 7 H19 M10 7 V5 H14 V7 M7 7 L8 19 H16 L17 7").view_box(0.0, 0.0, 24.0, 24.0);
    column()
        .gap(12)
        .align(Align::Start)
        .child(text("设置").font_size(20).font_weight(700).accessibility_role(Role::Heading).name("title")) // 推断不出的角色显式声明
        .child(text_field(name).accessibility_name("名字").placeholder("输入你的名字")) // 没有可见标签的输入框：直接起名字
        .child(label("城市").target(city_focus)) // 可见的标签：控件由它命名
        .child(text_field(city).focus_handle(city_focus))
        .child(checkbox(subscribe).label("订阅周报")) // 复选框旁边的文字也是它的名字
        .child(button(path(trash).size(16, 16).stroke(Stroke::new(1.5).round())).accessibility_name("清空").tooltip("清空")) // 只有图标的按钮一定要起名字
        .child(image("assets/cat.jpg").size(64, 64).accessibility_name("一只猫")) // 替代文字；没有的图片当装饰
        .child(text("✦").accessibility_hidden(true)) // 纯装饰
}
```

| 情况 | 怎么做 |
|---|---|
| 只有图标的按钮、没有文字的输入框和控件 | `.accessibility_name("名字")`：读屏软件念的名字 |
| 旁边有说明文字的控件 | 标签 `label(文字).target(句柄)`，控件 `.focus_handle(句柄)`：控件由标签命名（第 [14](14-基础控件.md) 章） |
| 有意义的图片 | `.accessibility_name("替代文字")`；没有替代文字的图片和矢量图标当装饰，辅助技术跳过 |
| 纯装饰、和旁边控件名字重复的文字 | `.accessibility_hidden(true)` |
| 推断不对的角色（标题、自己做的标签页、菜单项……） | `.accessibility_role(Role::Heading)` 等（`Role` 来自 AccessKit） |
| 自己画的复选框、开关 | `.accessibility_checked(信号)` |
| 选中、展开状态 | `.accessibility_selected(..)`、`.accessibility_expanded(..)` |
| 补充说明 | `.accessibility_description(..)`（提示 `.tooltip(..)` 的文字也会当描述） |
| 自己画的滑块、进度条 | `.accessibility_value(RangeValue::new(值, 最小, 最大))`，见下面 |
| 提示消息、保存成功之类 | `.accessibility_live(Live::Polite)` 实时区域，见下面 |

```rust
pub fn custom_slider() -> Element {
    let volume = signal(40.0f64);
    row()
        .width(200)
        .height(24)
        .radius(12)
        .background(Color::hex(0x3a3a3c))
        .focusable(true)
        .accessibility_name("音量")
        .accessibility_value(move || RangeValue::new(volume.get(), 0.0, 100.0).step(5.0)) // 数值和范围
        .accessibility_value_text(move || format!("{:.0}%", volume.get())) // 念这段文字而不是数字
        .on_value_request(move |v| volume.set(v)) // 辅助技术拖动、增大、减小
        .child(rect().height(24).radius(12).background(Color::hex(0x0a84ff)).width(move || volume.get() * 2.0))
}

pub fn status_line() -> Element {
    let status = signal(String::new());
    column()
        .gap(8)
        .align(Align::Start)
        .child(button("保存").on_click(move || status.set("已保存".into())))
        .child(text(move || status.get()).accessibility_live(Live::Polite)) // 内容一变读屏软件就念
}
```

有 `on_value_request` 的数值是滑块，没有的是进度条。`Live::Polite` 等当前的话念完再念，`Live::Assertive` 立即打断。

## 自己检查

- 测试里用 `Harness::accessibility()` 拿到整棵无障碍树检查（第 [20](20-测试.md) 章）。
- 手动：运行应用，按 ⌘F5 打开 VoiceOver（VO 键是 Control+Option），VO+→ 逐个元素走，VO+空格按下，VO+U 列出所有控件；再按 ⌘F5 关掉。
- 全部操作都应该能只用键盘完成：Tab 走一遍，看焦点环是不是落在每个能操作的地方。

## 坑

- 表格（行和列）、自己用按钮拼的标签页、菜单这些结构没有推断，要用 `.accessibility_role(..)`、`.accessibility_selected(..)` 显式声明角色和选中状态（第 [13](13-样式对象.md) 章的例子）。放在菜单里的按钮不会自动当成菜单项，要写 `.accessibility_role(Role::MenuItem)`。
- 自己画的内容（画布里的区域用 `hit_accessibility_name`，第 [15](15-图片与矢量图标.md) 章）；自己定义的元素实现 `AccessibilityProvider`（第 [25](25-自定义元素.md) 章）。
- Windows、Linux 上的无障碍适配编进去了，但没有在真机上验证过。
