# 10. 滚动

```rust
pub fn feed() -> Element {
    let feed = ScrollHandle::new();
    column()
        .height(480)
        .gap(8)
        .child(
            row()
                .justify(Justify::SpaceBetween)
                .align(Align::Center)
                .child(text("动态").font_size(20).font_weight(700).opacity(move || 1.0 - (feed.offset_y() / 200.0).clamp(0.0, 0.6))) // 滚动联动
                .child(button("回到顶部").on_click(move || feed.scroll_to(0.0, 0.0))), // 平滑滚过去
        )
        .child(
            scroll_y(column().gap(8).padding(12).children((1..=60).map(|i| text(format!("第 {i} 行")).padding(10).radius(6).background(SURFACE))))
                .grow(1) // 视口在滚动方向上要有大小：grow 或 height
                .scroll_handle(feed),
        )
}

pub fn carousel() -> Element {
    scroll_x(row().gap(12).padding(12).children((1..=12).map(|i| column().size(180, 120).padding(16).radius(8).background(SURFACE).border(1, LINE).child(text(format!("卡片 {i}"))))))
}

pub fn suggestions() -> Element {
    // 跟着内容长高：不到 240 时和内容一样高，再多就在里面滚动（下拉菜单、建议列表）
    scroll_y_fit(column().gap(2).padding(4).children((1..=12).map(|i| text(format!("建议 {i}")).padding_x(10).padding_y(6))))
        .max_height(240)
        .radius(6)
        .background(SURFACE)
        .border(1, LINE)
}
```

- `scroll_y(内容)` 竖向滚动，`scroll_x(内容)` 横向（高度跟着内容，适合轮播），`scroll(内容)` 两个方向（内容的宽度不跟视口走，通常要给内容指定大小）。
- `scroll_y_fit(内容)` 跟着内容长高：内容少时和内容一样高，长到 `max_height`（或者固定高度的父元素放不下）时才在里面滚动。下拉菜单的选项、建议列表、多行输入框都是这样。它要有上限；很长的列表用 `scroll_y` 或虚拟列表。
- 内容是一个合成层，**滚动时不重新布局、不重建图元**，只是平移。
- 手感：触控板 1:1 跟手、拉过边缘越拉越沉、松手回弹，惯性的减速和系统的一样；滚轮一格约 40 像素，平滑过去。惯性、回弹、平滑滚动、滚动条的淡入淡出在渲染线程上也推进一份：主线程卡住时照样滑，恢复后从屏幕上的位置接着走（虚拟列表往运动的方向多挂一些行，卡住时滑进来的也是挂好的）。嵌套时最内层能往这个方向滚的视口先滚，滚到头交给外层；竖着划过横向轮播滚的是外面的列表。滚轮每一格交给当时指针下的视口（连续滚的时候滚到头不中途换成外层，但指针移开了就交给指针下的），不用先点它。
- 键盘：方向键、翻页键、Home / End、空格滚动焦点所在（没有焦点时是指针下）的视口；Tab 把焦点移到视口外的元素时自动滚过去。
- 叠加式滚动条：滚动时淡入，停下 0.8 秒后淡出，指针靠近边缘时也显示、可以拖。`.scrollbar_color(..)` 改颜色。

`ScrollHandle` 是 `Copy` 的句柄：

| 方法 | |
|---|---|
| `offset()` / `offset_x()` / `offset_y()` | 当前偏移，**响应式**（滚动联动的绑定直接读它）；拉过边缘时是负数或超过最大值 |
| `max_offset()`、`viewport_size()`、`content_size()` | 范围和大小，响应式 |
| `scroll_to(x, y)` | 平滑滚过去（很远时先跳到附近再滑） |
| `jump_to(x, y)` | 立即跳过去 |
| `scroll_by(dx, dy)` | 相对滚动，连续调用会累加 |
| `scroll_to_index(i)` / `jump_to_index(i)` | 第 i 行（虚拟列表的第几项，普通视口是内容的第几个子元素）滚到顶上；行高量出来的列表里停得准，之后一直保持在那里，直到用户自己滚动 |

挂载之前发出的请求在第一次布局后执行；超出范围的目标夹到边缘。

触摸屏上手指拖动也一样滚（越过阈值才开始，带惯性和回弹），不用另外写，规则见第 [11](11-交互.md#触摸屏) 章。

## 坑

- **视口在滚动方向上不会被内容撑大**：`scroll_y` 不给 `.height(..)` 也没有 `.grow(1)` 时高度是 0，什么都看不到（调试构建会记一条警告）。`.grow(1)` 也要父元素在这个方向上有大小。这是故意的：这样十万行的内容不会把外面一路的容器都撑高。要跟着内容长高用 `scroll_y_fit`。
- 内容的内边距、间距写在**内容**上（跟着滚）；写在视口上就是不滚的边框。
- `scroll_handle` 只对 `scroll_x` / `scroll_y` / `scroll_y_fit` / `scroll` / `virtual_list` 返回的元素有效。
- 偏移是 `f32`：内容超过约一千六百万像素后精度不够（行高 72 时约二十万行）。
