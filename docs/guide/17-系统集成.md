# 17. 系统集成

本章的导入：

```rust
use aureole::prelude::*;
use aureole::clipboard::{self, ClipFormat, ClipboardContent};
use aureole::{Appearance, FileDialog, Notification, OpenSource};
```

## 文件对话框

```rust
pub fn open_text() -> Element {
    let content = signal(String::new());
    column()
        .gap(8)
        .align(Align::Start)
        .child(button("打开…").on_click(move || {
            aureole::spawn_local(async move {
                let Some(path) = FileDialog::new().title("选择文本文件").file_filter("文本", &["txt", "md"]).pick_file().await else {
                    return; // 取消了
                };
                let text = aureole::spawn_blocking(move || std::fs::read_to_string(path).unwrap_or_default()).await;
                content.set(text);
            });
        }))
        .child(text(move || content.get()).max_lines(10))
}

pub fn save_as() {
    aureole::spawn_local(async {
        if let Some(path) = FileDialog::new().file_name("导出.csv").save_file().await {
            let written = aureole::spawn_blocking(move || std::fs::write(path, "名字,数量\n苹果,3\n")).await;
            println!("写好了：{}", written.is_ok());
        }
    });
}
```

`FileDialog`（`use aureole::FileDialog`）：`.title(..)`、`.directory(..)`、`.file_name(..)`、`.file_filter(名字, &[扩展名])`，然后 `pick_file()`、`pick_files()`、`pick_directory()`、`save_file()`。对话框是异步的：开着时界面照常运行和动画；在窗口里调用时作为这个窗口的表单弹出（Windows、Linux 上是这个窗口的模态对话框）。返回的 future 只能在主线程等（在 `spawn_local` 里）。

- macOS：系统的打开、保存面板。`.filter` 的名字不显示，所有扩展名合在一起。
- Windows：系统的文件对话框，按 `.filter` 的名字分组显示，多于一组时最前面有一组"所有支持的文件"。
- Linux：桌面的文件对话框（经 XDG 门户，GNOME、KDE 都有），没有门户时用 zenity 或 kdialog，都没有时马上以空结果完成。

## 打开、通知、系统外观

```rust
pub fn integrations() -> Element {
    row()
        .gap(8)
        .child(button("复制链接").on_click(|| aureole::clipboard::write_text("https://www.rust-lang.org")))
        .child(button("粘贴").on_click(|| {
            if let Some(text) = aureole::clipboard::read_text() {
                println!("剪贴板：{text}");
            }
        }))
        .child(button("打开网址").on_click(|| aureole::open_url("https://www.rust-lang.org")))
        .child(button("在访达中显示").on_click(|| aureole::reveal_path(std::env::temp_dir())))
        .child(button("发通知").on_click(|| aureole::notify("导出完成", "已保存到下载文件夹")))
}

pub fn appearance() -> Element {
    text(move || if aureole::system_appearance().is_dark() { "系统现在是深色" } else { "系统现在是浅色" }.to_string())
        .padding(12)
        .background(move || if aureole::system_appearance() == Appearance::Dark { Color::hex(0x1c1c1e) } else { Color::WHITE })
        .color(move || if aureole::system_appearance() == Appearance::Dark { Color::WHITE } else { Color::BLACK })
}
```

- `clipboard::read_text`、`write_text` 是纯文字，和输入框的复制粘贴是同一个。别的格式见下面的"剪贴板"。
- `aureole::open_url(网址)` 用默认应用打开（`https://`、`mailto:`……）；`aureole::open_path(路径)` 用默认应用打开文件、在访达里打开文件夹；`aureole::reveal_path(路径)` 在访达里显示并选中（Windows 是资源管理器，Linux 是文件管理器，不支持选中时打开所在的文件夹）。路径不存在时返回 `false`。
- `aureole::notify(标题, 正文)` 发系统通知，系统通知不可用时把内容记下来（`tracing` 的 info）、返回 `false`：
  - **macOS 上要打包成 .app 才能发**（第 [23](23-打包与发布.md) 章），第一次发时系统请求权限；没打包时（`cargo run`）不可用。
  - **Windows 上要有应用标识（AppUserModelID）**：从安装程序建的开始菜单快捷方式启动（快捷方式带着标识）或打成 MSIX 包；直接运行可执行文件（`cargo run`）时不可用。
  - Linux 上发给桌面的通知服务，不用打包。
- `aureole::beep()` 放一下系统的提示音（用户在系统设置里选的那一个），比如按了做不了的键。Linux 的桌面没有统一的提示音，返回 `false`；测试工具里不出声，`Harness::beep_count()` 数次数。
- `aureole::system_appearance()` 是系统外观（`Appearance::Light` / `Dark`），响应式：用户在系统设置里切换时绑定它的属性自动更新。它只是一条系统信息：框架默认的样子只有浅色，不跟着它变；想让自己的界面跟着系统变深，就像上面这样在绑定里读它换颜色（样式对象里的值也能绑定）。Linux 上读桌面的外观设置（XDG 门户），GNOME、KDE 都支持。
- `aureole::system_accent_color()` 是系统的强调色（`Option<Color>`），响应式，读不到时是 `None`。框架不自动用它，想跟着系统时在自己的样式对象里读：`Style::new().background(move || aureole::system_accent_color().unwrap_or(默认色))`。
- `aureole::is_motion_reduced()` 是系统的"减少动态效果"，响应式；框架自己的滑动、共享元素的飞行、关键帧里的移动已经按它处理，自己声明的过渡要不要跟着它由你决定。

## 剪贴板：图片、文件、带格式的文字

```rust
pub fn rich_clipboard() -> Element {
    let pasted = signal(None::<RgbaImage>);
    column()
        .gap(8)
        .align(Align::Start)
        .child(button("复制图片").on_click(|| {
            let picture = RgbaImage::new(2, 1, vec![32, 99, 235, 255, 32, 99, 235, 128]);
            clipboard::write(ClipboardContent::new().image(picture).text("一张图")); // 同时放图片和文字
        }))
        .child(button("复制带格式的文字").on_click(|| {
            clipboard::write_rich_text([span("加粗").font_weight(700), span("，普通，"), span("文档").link("https://www.rust-lang.org")]);
        }))
        .child(button("粘贴图片").on_click(move || {
            if clipboard::formats().contains(&ClipFormat::Image) {
                pasted.set(clipboard::read_image());
            }
        }))
        .child_when(move || pasted.with(Option::is_some), move || image(pasted.get().expect("上面查过")).size(120, 80)) // 直接给 image()
        .child(button("复制文件路径").on_click(|| clipboard::write_files([std::env::temp_dir()])))
}
```

- `clipboard::formats()` 查现在有哪些格式（`ClipFormat::Text`、`RichText`、`Image`、`Files`）。剪贴板是用户的，别的程序随时会改：查到有也可能下一刻就没了，读的时候还是要处理 `None`。
- `write_image`、`write_files`、`write_rich_text` 各放一种。`clipboard::write(ClipboardContent::new()...)` 一次放几种，同一份内容的几种表示：能贴图片的地方贴图片，只认文字的地方贴文字。什么都没有的内容是清空。
- 读出来的图片是 `RgbaImage`（宽、高、RGBA 像素），能直接给 `image()`；自己的像素用 `RgbaImage::new(宽, 高, 像素)`。
- 带格式的文字是一串 `span`，读出来也是，放进 `rich_text()` 就能显示。保留得下的样式：粗体、斜体、下划线、删除线、字号、颜色、字体、行内代码（等宽）、链接。`Span::info()` 读一段的内容和样式。
- 输入框只认文字：剪贴板里只有图片时粘贴不到东西，按键接着冒泡，想接图片就在外面的 `on_key_down` 里读 `read_image`。
- 各平台能放哪些格式查 `aureole::capabilities()`（`supports_clipboard_image`、`supports_clipboard_files`、`supports_clipboard_rich_text`、`supports_clipboard_multiple_formats`）。macOS、Windows 都能；Linux 上一次只放一种（文件、图片、文字里最优先的），带格式的文字只剩纯文字。

## 带按钮的通知

```rust
pub fn notification() -> Element {
    let status = signal(String::new());
    column()
        .gap(8)
        .align(Align::Start)
        .child(button("导出").on_click(move || {
            let sent = Notification::new("导出完成")
                .body("已保存到下载文件夹")
                .action("打开", move || status.set("点了打开".into()))
                .action("稍后", move || status.set("点了稍后".into()))
                .on_click(move || status.set("点了通知".into()))
                .show();
            if let Err(error) = sent {
                status.set(format!("通知发不了：{error}")); // cargo run 时：需要打包
            }
        }))
        .child(text(move || status.get()))
}
```

- `Notification::new(标题)` 加 `.body(正文)`、`.action(文字, 处理器)`、`.on_click(处理器)`，`.show()` 发出去。发不了时是错误，`PlatformError::NotPackaged` 是要先打包（macOS 的 .app、Windows 的应用标识），`Unsupported` 是没有通知服务。前提和 `aureole::notify` 一样。
- 处理器在主线程、在创建通知时的作用域里执行，直接写信号。点一次就用掉了；发通知的元素卸载以后再点什么都不发生，要一直收得到就在根上（`App::new` 之前建的信号，或者菜单的处理器里）发。
- `show` 返回 `Ok` 只说明交给了系统。权限是异步问的：用户或者系统拒绝了（macOS 27 上临时签名的包会被拒绝）时只记一条错误，通知不显示。
- 按钮怎么显示由系统决定：macOS 上通知样式设成"横幅"时要把指针放上去才看得到，Linux 看桌面的通知服务。应用退出以后再点通知，处理器已经不在了。
- 测试工具里不真的发：`h.notifications()` 读回来，`h.click_notification(第几条)`、`h.press_notification_action(第几条, 第几个按钮)` 模拟用户点，下一帧调用处理器。

## 打开网址和文件、单实例

```rust
pub fn notes_main() {
    let opened = signal(Vec::<String>::new()); // 在 App::new 之前创建：处理器和界面都用它
    App::new(move || text(move || opened.with(|list| list.join("\n"))).padding(24))
        .title("笔记")
        .single_instance("com.example.notes") // 再运行一次：参数转给这个实例，新进程退出
        .on_open(move |request| {
            if let OpenSource::SecondInstance(args) = &request.source {
                println!("又启动了一次，参数 {args:?}"); // 窗口已经带到了最前面
            }
            opened.update(|list| {
                list.extend(request.urls.iter().cloned()); // notes://note/42，原样
                list.extend(request.files.iter().map(|file| file.display().to_string())); // 绝对路径
            });
        })
        .run();
}
```

- `on_open` 收到应用被要求打开的网址（自定义协议）和文件，`request.source` 说明从哪里来：
  - `Launch`：启动时的命令行参数（以 `-` 开头的选项、不存在的文件不算），macOS 打包后系统为了打开它们而启动应用时交来的；
  - `System`：运行中由系统交来（macOS 打包后，在访达里打开文档、点了 `notes://` 链接）；
  - `SecondInstance(参数)`：开了单实例时，再次启动的进程转来的，带着它的命令行参数。
- 处理器在主线程、主窗口建好之后调用（之前到的先排队），可以直接写界面的信号、开新窗口。只关心一种时看请求里的 `urls` 或 `files`。
- `single_instance(true)` 用可执行文件名当标识，也可以给一个字符串（发布的应用最好给，比如包标识符）。同一个用户再启动时新进程把参数转过来就退出，正在运行的实例把最近用过的窗口带到最前面。两个同时启动也只留一个；上次崩溃留下的文件会被清掉。打包的和 `cargo run` 的行为一样。
- 协议和文档类型要在打包设置里声明（`url-schemes`、`document-types`，第 [23](23-打包与发布.md) 章），系统才知道把它们交给这个应用。
- 测试里用 `aureole::testing::simulate_open(OpenRequest { .. })` 模拟系统交来的请求，和真的走同一条路。

## 坑

- Windows、Linux 上文件对话框的结果在对话框自己的线程里交回来，`.await` 之后的代码仍在主线程，照常读写信号。
- Linux 上没有 XDG 门户、也没装 zenity / kdialog 时，文件对话框马上以空结果完成（记一条错误）。
- 测试工具里剪贴板、通知换成了进程内的替身，系统外观固定为浅色、强调色固定为 `None`，测试不碰用户的系统状态。
- macOS 上没打包（`cargo run`）时点链接、双击文档不会交给这个进程：协议和文档类型是 .app 的 Info.plist 声明的。没打包时只看命令行参数：`cargo run -- notes://note/42`。
- 选项的值如果恰好是存在的文件，也会被当成要打开的文件（`--log out.txt`）：要区分时自己解析 `SecondInstance` 带来的参数。
- macOS 14 起，别的应用在前面时系统可能不让后台的应用自己激活：再次启动后窗口会被还原、放到前面，但不一定拿到焦点。
