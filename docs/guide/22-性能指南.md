# 22. 性能指南

这一章讲写应用时要知道的开销模型：什么便宜、什么贵、怎么自己看。

框架的做法是**只做变了的部分**：写入相同的值什么都不做，能原地修补的不重新生成，能交给合成层的不碰主线程，画面不变时连线程都不醒。

## 什么开销低

从便宜到贵：

| 改了什么 | 框架做什么 |
|---|---|
| 写入和原来相同的值 | 什么都不做 |
| 透明度、缩放、旋转、平移的**动画**（声明了 `.transition`、时间线） | 合成层：渲染线程采样同一条轨道，主线程不布局、不生成图元，卡住了也不掉帧 |
| 滚动 | 合成层平移；虚拟列表跨过行边界时才挂载新行 |
| 背景色、边框、圆角、一层投影 | **原地修补**：只改显示列表里那几个图元，渲染线程只上传改过的几段。不布局、不重新生成 |
| 半透明元素的透明度（改完还是半透明） | 只改它的合成层 |
| 平移、缩放、旋转（没声明动画）、模糊、渐变、几层投影、文字颜色 | 重新生成显示列表，不布局。普通的方块走快路径，排版和位置都没变的文字整块拷贝留着的字形图元 |
| 宽高、内边距、间距、对齐（布局属性） | 重新布局 + 重新生成；动画期间每帧都这样 |
| 文字内容、字号、字重 | 重新排版改了的这一段（输入框只排改了的段），再重新布局 + 重新生成 |
| 半透明的容器、模糊、背景模糊、滤镜、遮罩、混合模式 | 每帧多离屏渲染；内容没变、只有变换和透明度在动时直接合成缓存的纹理 |

几条由此而来的建议：

- **会动的东西用合成层**：位移用 `translation`，大小变化能用 `scale` 就别用宽高；淡入淡出用 `opacity`。宽高、内边距的动画每帧重新布局，只放在少量元素上。
- **静态值别写成闭包**：`.padding(16)` 没有任何开销，`.padding(move || 16.0)` 多一个副作用。
- **样式对象没有状态时不多花**：和直接写链式方法一样多的响应式节点；有状态的每个元素多一个记状态的信号、每个按状态换值的属性一个绑定（第 [13](13-样式对象.md) 章）。控件没有内置动画，悬停、按下只改一两个绘制属性，走原地修补。
- **长列表用虚拟列表**；`each` 的 key 要稳定。
- **别在绑定里克隆大数据**：用 `with(|v| ..)` 借用着读；派生的列表、筛选结果放进 `memo`，相等时下游什么都不做。
- **主线程别做重活**：读文件、解析、计算放进 `spawn_blocking`，结果用 `then` 交回来。主线程卡住时合成层动画照常，但布局、输入、主线程上的动画会停。
- **离屏有代价**：半透明、模糊用在卡片、浮层这种局部，别铺在一大片列表外面；透明度回到 1 的分组直接画在原处。里面东西多又要整体动的卡片用 `.group_cache(true)`（第 [5](05-样式与视觉.md) 章）。
- **文字重新排版是主要开销**：一帧改上千段文字时最明显。只改颜色不排版。
- 测性能用 `--release`，关掉低电量模式。

## 画面不变时什么都不做

每个窗口有一个帧时钟（macOS 的显示链接、Windows 的合成器时钟或垂直消隐、Wayland 的帧回调、X11 的计时器）。连续几帧什么都没做就暂停，事件循环一直睡到有事：窗口事件、到期的定时器、做完的任务、别的线程的投递。没有轮询。

"要不要帧"从真实的状态读，分三种（`NextFrame`）：

| | 什么时候 | 例子 |
|---|---|---|
| 不要（`Idle`） | 什么都不在动 | 静止的页面 |
| 按时刻要（`At(时刻)`） | 只有某个时刻要变一下：窗口睡到那一刻，出一帧再睡 | 输入框的插入点闪烁，有焦点时每秒只醒两次左右 |
| 每帧都要（`Continuous`） | 确实每帧都在变 | 在动的动画、滚动的惯性、在播的动图、`Shader::animated(true)` 的着色器 |

所以**让窗口一直出帧的只有真的在动的东西**。一直循环的动画（`Tween::forever`、循环的时间线）会让窗口每帧都醒，用在看得见的地方，看不见了就停掉（`child_when` 卸载它、`stop()`）。动图滚出视口、窗口被挡住时不换帧。

测试里检查自己的界面静止时不要帧：`h.wants_frames()`、`h.next_frame()`（第 [20](20-测试.md) 章）；真实窗口里 `aureole::performance::event_loop_wakeup_count()` 数事件循环醒了几次。

## 一帧里发生什么

主线程每帧：执行投递过来的工作和就绪的任务 → 推进滚动和主线程上的动画 → 需要时重新布局 → 需要时生成或修补显示列表 → 把变化交给渲染线程。渲染线程按同一个动画时钟采样合成层、上传、提交给 GPU。

| 主线程 | 渲染线程 |
|---|---|
| 事件、输入法、定时器、异步任务，信号和绑定 | 收下图元、图集、合成层的变化，上传到 GPU |
| 布局、文字排版、生成图元（显示列表） | 合成层动画（透明度、缩放、旋转、平移）：和主线程按同一个动画时钟、同一个时刻采样同一条轨道 |
| 非合成层属性的动画（颜色、宽高……），退场 | 滚动的惯性、回弹、平滑滚动、滚动条淡入淡出：和主线程各推进一份，上屏的是这一份 |
| 命中测试、悬停、虚拟列表挂载行（按主线程那份滚动偏移） | 编码、提交、呈现 |

平时两边每帧一来一回；主线程卡住（超过 1.5 帧没来消息）时渲染线程自己出帧，合成层动画和滚动照样走，滚动推进到的状态在主线程恢复后交回去（积压的点击按屏幕上的位置命中）。

## 自己看每帧做了什么

测试工具（`use aureole::testing::Harness;`）的 `frame()`、`advance(..)` 返回 `FrameStats`：布局、生成图元做没做，改了几个图元，图元和合成层数，在动的动画数，各花了多久。用它写成测试，改坏了马上知道（第 [20](20-测试.md) 章）：

```rust
/// 每帧做了哪些工作：改颜色只修补那几个图元，什么都没变时什么都不做
pub fn frame_work() {
    let shift = signal(0u32);
    let cells = (0..1000u32).map(move |i| rect().height(12).background(move || Color::hsv(turns((i + shift.get()) as f32 / 1000.0), 0.6, 0.9)));
    let h = Harness::new(800.0, 600.0, grid().columns([fr(1); 20]).gap(2).children(cells));
    let first = h.frame();
    println!("首帧：布局 {:.2}ms，生成图元 {:.2}ms，{} 个图元", first.layout_time.as_secs_f32() * 1000.0, first.paint_time.as_secs_f32() * 1000.0, first.quads);
    shift.set(1);
    let recolor = h.frame();
    assert!(!recolor.laid_out && recolor.repainted); // 绘制属性：不布局，只修补改了的图元（recolor.patched_quads 个）
    let idle = h.frame();
    assert!(!idle.laid_out && !idle.repainted); // 什么都没变：什么都不做
}

/// 平移在合成层上（不布局、不重建图元）；宽度是布局属性（每帧重新布局）
pub fn layer_vs_layout() {
    let moved = signal(false);
    let slide = rect().size(50, 50).translation_x(move || if moved.get() { 200.0 } else { 0.0 }).transition(Property::TranslationX, Spring::smooth());
    let h = Harness::new(400.0, 200.0, column().child(slide));
    h.frame();
    moved.set(true);
    h.frame();
    let mid = h.frame();
    assert!(mid.animations > 0 && !mid.laid_out && !mid.repainted);

    let wide = signal(false);
    let grow = rect().height(50).width(move || if wide.get() { 300.0 } else { 50.0 }).transition(Property::Width, Spring::smooth());
    let h = Harness::new(400.0, 200.0, column().child(grow));
    h.frame();
    wide.set(true);
    h.frame();
    let mid = h.frame();
    assert!(mid.animations > 0 && mid.laid_out);
}
```

120Hz 时一帧是 8.3 ms。静止的界面不布局、不生成图元、不重画；出现预料之外的布局、重画，先看是不是把绘制属性写成了布局属性，或者绑定的值每次都不一样。

## 资源用量


应用里能读到启动时间、CPU、内存、显存这些数据（`aureole::performance`，用的都是不需要权限的系统接口；这个平台拿不到的项是 `None`）：

```rust
/// 本进程的常驻内存、CPU 时间，渲染器分配的显存；打开记录后窗口里每帧的耗时
pub fn resource_usage() {
    let usage = performance::usage();
    let mb = |bytes: Option<u64>| bytes.unwrap_or(0) as f64 / (1024.0 * 1024.0);
    println!("常驻内存 {:.1} MB，物理占用 {:.1} MB，CPU 时间 {:?}", mb(usage.resident), mb(usage.footprint), usage.cpu);
    println!("显存 {:.1} MB（图集、图片、离屏、缓冲区）", performance::gpu_memory().total() as f64 / (1024.0 * 1024.0));
    if let Some(gpu) = performance::gpu_info() {
        println!("GPU：{gpu}"); // 比如"Apple M4 Pro（Metal，集成显卡）"；还没有窗口时是 None
    }
    performance::set_frame_recording(true); // 之后窗口里主线程每帧、渲染线程每次绘制的耗时都记下来
    // …… 跑一段 ……
    performance::set_frame_recording(false);
    let frames = performance::take_frame_times();
    println!("主线程每帧 p50 {:?}，p99 {:?}", performance::percentile(&frames.main, 0.5), performance::percentile(&frames.main, 0.99));
}
```

`performance::first_present()` 是从进程启动到第一帧上屏用了多久（用 `cargo run` 启动时不算构建的时间）。启动的每一段用了多久按 debug 级别记在 `tracing` 的 `aureole::startup`、`aureole::pipeline` 两个目标下，装上订阅者、打开这两个目标就能看。
