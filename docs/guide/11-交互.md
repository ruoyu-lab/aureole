# 11. 交互：指针、键盘、焦点、快捷键

这一章先讲输入怎么变成处理器的调用：事件怎么传、处理器怎么写、怎么取消内置行为、几个元素都想要同一个手势时谁拿到；再讲焦点、按键的顺序、快捷键，最后是拖放。

"指针"是鼠标、触控板、笔、触摸的统称，事件都按指针说；"鼠标"只指那个设备（`MouseButton`）。

## 指针

```rust
pub fn pressable() -> Element {
    let (hovered, pressed) = (signal(false), signal(false));
    row()
        .padding_x(16)
        .height(40)
        .radius(10)
        .align(Align::Center)
        .background(move || match (hovered.get(), pressed.get()) {
            (_, true) => Color::hex(0xe3e7ec),
            (true, false) => FILL,
            _ => SURFACE,
        })
        .transition(Property::Background, Tween::new(ms(120)))
        .scale(move || if pressed.get() { 0.96 } else { 1.0 })
        .transition(Property::Scale, Spring::snappy())
        .cursor(Cursor::Pointer)
        .on_hover(move |inside| hovered.set(inside))
        .on_press(move |down| pressed.set(down))
        .on_click(|| println!("点了"))
        .on_double_click(|e: &ClickEvent| println!("双击，元素里的位置 {:?}", e.position))
        .child(text("按我"))
}
```

| 事件 | 什么时候 |
|---|---|
| `on_click(..)` | 按下和松开都在元素上（合成在两次都在其下的最内层元素上，再往外冒泡）；有焦点时回车、空格；辅助技术；点标签 |
| `on_hover(\|进入\| ..)` | 进入（`true`）、离开（`false`），子元素上方也算在里面；不传播 |
| `on_press(\|按下\| ..)` | 按下、松开，用来做按压反馈 |
| `on_double_click(..)` | 第二次按下时（0.4 秒、4 像素以内；手指是第二下抬起时，24 像素以内）；两次点击各自照常触发 `on_click` |
| `on_secondary_click(..)` | 右键按下时（macOS 上 Control+左键、手指长按也算），用来弹右键菜单 |
| `on_middle_click(..)` | 中键 |
| `on_pointer_down(..)` / `on_pointer_up(..)` / `on_pointer_move(..)` | 指针按下、松开、移动；移动只在指针真的动了时发，布局变了、滚过以后刷新悬停不发 |
| `on_pointer_enter(..)` / `on_pointer_leave(..)` | 进入、离开（带事件对象的 `on_hover`），不传播 |
| `on_pointer_cancel(..)` | 进行中的按下被打断：窗口失去焦点，拖动交给了外面的元素，手指拿去滚动了，系统收走了手指 |
| `on_wheel(..)` | 滚轮、触控板滚动，在滚动视口滚之前 |
| `on_drag(..)` | 拖动 |
| `on_pinch(..)` / `on_rotate(..)` | 双指捏合、旋转：触控板，触摸屏上两根手指 |

同样的悬停、按下换颜色用样式对象写更短，元素自己记状态（第 [13](13-样式对象.md) 章）；`on_hover`、`on_press` 适合要拿状态做别的事的时候。

`PointerEvent` 里有 `position`（元素自己的坐标，去掉了变换）、`window_position`（窗口坐标）、`button`、`buttons`、`modifiers`、`clicks`、`device`（鼠标、触控板、笔、触摸）、`pointer_id`（触摸屏上哪根手指）、`time`；`ClickEvent` 还有 `source`（指针、键盘、辅助技术、标签）。

`.cursor(Cursor::..)` 设置指针形状（`Pointer`、`Text`、`Grab`、`Grabbing`、`Move`、`Crosshair`、`NotAllowed`、`ResizeHorizontal`……），指针下最内层设置了形状的元素决定，可以绑定信号。

## 事件怎么传

指针、点击、滚轮、按键都沿一条路走三段：

```text
捕获：从最外面往里，到目标的父元素（on_*_capture）
目标：指针下最内层的元素；按键是有焦点的元素（先 on_*_capture，再 on_*）
冒泡：从目标的父元素往外（on_*）
最后：没被取消的内置行为（拿焦点、选字、滚动、Tab……）
```

路径在分发前拍下来，处理器里改了树也按这条路走完（卸载了的元素跳过）。

```rust
/// 一次按下走三段：外层的捕获 → 目标 → 外层的冒泡
pub fn phases() -> Element {
    let log = signal(Vec::<String>::new());
    let note = move |who: &'static str| move |e: &PointerEvent| log.update(|l| l.push(format!("{who} {:?}", e.phase())));
    column()
        .padding(16)
        .gap(8)
        .on_pointer_down_capture(note("外层"))
        .on_pointer_down(note("外层"))
        .child(row().padding(12).radius(6).background(FILL).name("inner").on_pointer_down(note("里层")).child(text("按这里")))
        .child(text(move || log.with(|l| l.join(" → "))).name("log"))
}
```

按下"按这里"，下面那行文字是 `外层 Capture → 里层 Target → 外层 Bubble`。`e.phase()` 说明事件现在走到哪一段。

| | 事件 |
|---|---|
| 走完三段 | `on_pointer_down`、`on_pointer_up`、`on_pointer_move`；`on_click`、`on_secondary_click`、`on_middle_click`、`on_double_click`；`on_wheel`；`on_key_down`、`on_key_up`；`on_field_change`（都有 `_capture` 的一份） |
| 只有开始的一下走三段，决定谁拿到 | `on_drag`、`on_pinch`、`on_rotate`（有 `_capture` 的一份，见下面"手势的仲裁"） |
| 只发给元素自己 | `on_hover`、`on_pointer_enter`、`on_pointer_leave`、`on_focus`、`on_scroll`、`on_change`、`on_commit`、`on_drop`、`on_file_drop` |

按压反馈 `on_press` 跟着指针按下走：按下传到了的元素都收到，里面的元素停止传播以后外面的就不再按下。禁用的元素在传播时跳过，外面没禁用的照常收到。同一个元素上的几个处理器按添加的顺序调用，基础控件自己的处理器排在你加的后面。

### 停止传播

嵌套的可点击元素都收到点击。里面的处理完不想让外面再收到，调用 `e.stop_propagation()`：

```rust
/// 点击从里往外冒泡：点里面的行，外面的卡片也收到，除非行停止传播
pub fn nested_clicks() -> Element {
    column()
        .padding(12)
        .radius(10)
        .background(FILL)
        .on_click(|| println!("卡片")) // 点卡片里没停止传播的地方，卡片收到
        .child(text("卡片"))
        .child(row().padding(8).on_click(|e: &ClickEvent| {
            println!("这一行");
            e.stop_propagation(); // 外面的卡片不再收到
        }).child(text("这一行")))
}
```

- 冒泡时外面的元素不再收到，捕获时里面的元素不再收到；**同一个元素上的别的处理器照样调用**。
- 基础控件（按钮、复选框、下拉框……）处理完自己的点击、按键都停止传播；输入框也不让点击往外传，点可点击行里的输入框不会触发这一行。

### 取消内置行为

`e.prevent_builtin(Builtin::…)` 取消事件之后的内置行为，和传播没有关系。工具栏的按钮按下时不该抢走输入框的焦点：

```rust
/// 工具栏的按钮：按下时不抢焦点，插入点留在输入框里
pub fn keep_focus() -> Element {
    let (note, bold) = (signal(String::new()), signal(false));
    row()
        .gap(8)
        .align(Align::Center)
        .child(text_field(note).name("note").width(200))
        .child(
            text("粗")
                .name("bold")
                .padding_x(10)
                .padding_y(4)
                .radius(4)
                .background(move || if bold.get() { ACCENT_SOFT } else { FILL })
                .focusable(true) // Tab 照样走得到
                .on_pointer_down(|e: &PointerEvent| e.prevent_builtin(Builtin::FOCUS)) // 指针按下时不拿焦点
                .on_click(move || bold.update(|b| *b = !*b)),
        )
}
```

| `Builtin::` | 取消什么 | 在哪个处理器里取消 |
|---|---|---|
| `FOCUS` | 按下时拿焦点 | `on_pointer_down` |
| `TEXT_SELECT` | 按下、拖动时放插入点、选字 | `on_pointer_down` |
| `DRAG` | 按下后移动时开始拖动 | `on_pointer_down` |
| `ACTIVATE` | 合成点击；回车、空格激活有焦点的元素 | `on_pointer_down`、`on_pointer_up`；`on_key_down` |
| `CONTEXT_MENU` | 右键点击（`on_secondary_click`），手指长按也是 | `on_pointer_down` |
| `DISMISS` | 按在外面、按 Esc 时请求关闭浮层（第 [12](12-浮层.md) 章） | `on_pointer_down`；`on_key_down_capture` |
| `SCROLL` | 滚轮、方向键、翻页键、手指拖动滚动视口 | `on_wheel`；`on_key_down`；`on_pointer_down`（手指） |
| `TAB` | Tab、Shift+Tab 切换焦点 | `on_key_down` |
| `ARROWS` | `focus_arrows` 的方向键；输入框里的方向键移动插入点 | `on_key_down` |
| `EDIT` | 输入框处理按键：打字、删除、移动插入点、剪贴板、撤销 | `on_key_down` |
| `CLOSE` | 用户点关闭按钮时关窗口 | `Window::on_close_request`（第 [18](18-多窗口菜单栏托盘.md) 章） |
| `ALL` | 全部 | |

停止传播和取消内置行为是两件事：

- **指针**：停止传播只管传播，拿焦点、选字、拖动照常，要取消就 `prevent_builtin`。
- **按键**：停止传播就是"这个键我处理了"，快捷键和 Tab、激活、滚动这些内置行为都不再做。只想取消其中一样、让别的元素接着收到时用 `prevent_builtin`。

### 处理器的写法：什么时候要写参数类型

处理器的返回值都丢掉，所以 `.on_click(|| aureole::open_url(..))` 这样有返回值也能直接写（按键和关窗口除外，见下面）。**参数怎么写**分三类，最容易踩坑的是第一类：

```rust
/// 处理器的几种写法
pub fn handler_forms() -> Element {
    let (count, name) = (signal(0), signal(String::new()));
    let bump = move || count.update(|n| *n += 1);
    column()
        .gap(8)
        .on_click(bump) // 不收参数：用不到事件对象时最短
        .on_click(|e: &ClickEvent| println!("{:?}", e.source)) // 收事件对象：要写出参数的类型
        .on_pointer_move(|e: &PointerEvent| println!("{:?}", e.position)) // 同上
        .on_hover(|inside| println!("{inside}")) // 收 bool 的：只有一种写法，不用写类型
        .on_key_down(|e| {
            // 按键也只有一种写法：一定收事件对象，不用写类型
            if e.is("Escape") {
                e.stop_propagation();
            }
        })
        .child(
            text_field(name)
                .on_change(|t| println!("{t}")) // 改值：收新的值，类型能推断
                .on_commit(|e: &ChangeEvent<String>| println!("{:?}", e.source)), // 或者收整个事件对象：写出类型
        )
}
```

| 处理器 | 写法 | 要写类型吗 |
|---|---|---|
| 收事件对象的大部分：`on_click` 一族、`on_pointer_*`、`on_wheel`、`on_scroll`、`on_drag`、`on_pinch`、`on_rotate`、`on_drag_enter`、`on_drag_over`、`on_drag_leave`、`on_file_drop`、`on_field_change`，和它们的 `_capture` | 不收参数 `\|\| ..`，或者收事件对象 `\|e: &ClickEvent\| ..` | **要**：同一个方法接受两种闭包，编译器推断不出来 |
| 按键：`on_key_down`、`on_key_up` 和它们的 `_capture`；`Window::on_close_request` | 一定收事件对象 `\|e\| ..`，返回 `()` | 不用（`\|e: &KeyEvent\|` 也行） |
| 收普通的值：`on_hover`、`on_press`、`on_focus`、`on_file_hover`（`bool`），`on_dismiss`（`Dismiss`），`on_submit`（`String`） | `\|值\| ..` | 不用 |
| 改值：`on_change`、`on_commit` | 只收值 `\|v\| ..`，或者收事件对象 `\|e: &ChangeEvent<T>\| ..` | 收值时一般不用，参数只拿去做 `&str` 这类有歧义的用法时写 `\|t: String\|`；收事件对象时要 |
| 拖放：`on_drop`、`accepts_drop` | `\|数据: T, e\| ..`、`\|数据: &T\| ..` | **要写数据的类型**：它决定接收什么 |

第一类最常见的三个编译错误，都是闭包的写法不对：

```text
.on_click(|e| println!("{:?}", e.position))               // E0282 type annotations needed：不知道 e 是什么
.on_click(|_| save())                                     // E0277 闭包没有实现 IntoHandler：|_| 也算没写类型
.on_click(|e: &ClickEvent| println!("{:?}", e.position))  // 这样写
.on_click(|| save())                                      // 用不到事件对象时这样写
```

按键处理器相反：

```text
.on_key_down(|| save())                  // E0593：一定要收事件对象
.on_key_down(|e: &KeyEvent| true)        // E0308：不能返回值。处理了就调用 e.stop_propagation()，不会被悄悄丢掉
.on_key_down(|e| e.stop_propagation())   // 这样写
```

还有一个相邻的坑：
- 闭包要 `move`，捕获的是信号这样 `Copy` 的句柄，不要捕获引用。

### 指针捕获

`e.capture_pointer()`（按下时调用）：之后的移动、松开都交给这个元素，移出它、移出窗口也一样。自己做滑块这类控件时用：

```rust
/// 自己做的滑块：按下时捕获指针，拖到元素外面、窗口外面都还收到移动
pub fn captured_slider() -> Element {
    let (value, down) = (signal(0.5f32), signal(false));
    let at = move |e: &PointerEvent| value.set((e.position[0] / 200.0).clamp(0.0, 1.0));
    rect()
        .size(200, 8)
        .radius(4)
        .background(LINE)
        .on_pointer_down(move |e: &PointerEvent| {
            e.capture_pointer(); // 之后的移动、松开都交给这个元素
            down.set(true);
            at(e);
        })
        .on_pointer_move(move |e: &PointerEvent| {
            if down.get_untracked() {
                at(e);
            }
        })
        .on_pointer_up(move || down.set(false))
        .on_pointer_cancel(move || down.set(false)) // 窗口失去焦点这类打断
        .child(rect().height(8).radius(4).background(ACCENT).width(move || value.get() * 200.0))
}
```

`on_drag` 已经带着指针捕获，能用它的时候不用自己捕获；要按下就有反应、不等越过 4 像素才用上面这样的写法。

### 滚轮和滚动

滚轮先交给指针下的元素走三段，之后滚动视口才滚。`e.prevent_builtin(Builtin::SCROLL)` 就不滚，比如按住修饰键滚动时缩放：

```rust
/// 按住 Ctrl 或 Command 滚动是缩放，不滚动；平时照常滚
pub fn zoomable_list() -> Element {
    let zoom = signal(1.0f32);
    scroll_y(column().gap(8).padding(12).children((1..=40).map(|i| text(format!("第 {i} 行")))).scale(zoom))
        .name("zoomable")
        .height(240)
        .on_wheel(move |e: &WheelEvent| {
            if e.modifiers.has_control() || e.modifiers.has_super() {
                e.prevent_builtin(Builtin::SCROLL); // 这一下不滚动
                let steps = match e.delta {
                    WheelDelta::Lines([_, y]) => y,
                    WheelDelta::Pixels([_, y]) => y / 40.0,
                };
                zoom.update(|z| *z = (*z * (1.0 - steps * 0.1)).clamp(0.5, 3.0));
            }
        })
}
```

`WheelEvent` 里有 `delta`（`aureole::WheelDelta`：`Lines` 鼠标滚轮按格，`Pixels` 触控板按逻辑像素；正数让偏移变大）、`phase`、`inertial`（系统在手指抬起后接着发的惯性）、位置和修饰键。

滚动视口的 `.on_scroll(|e: &ScrollEvent| ..)` 是另一回事：**偏移变了以后**一帧发一次，不管是滚轮、拖滚动条、键盘还是代码滚的，不能取消。要的只是读偏移的绑定时，用 `ScrollHandle::offset_y()` 更短（第 [10](10-滚动.md) 章）；要做一次性的事时用它：

```rust
/// 滚过 200 像素才出现"回到顶部"：偏移变了时一帧发一次
pub fn back_to_top() -> Element {
    let (far, list) = (signal(false), ScrollHandle::new());
    column()
        .height(300)
        .gap(8)
        .child(
            scroll_y(column().gap(8).children((1..=60).map(|i| text(format!("第 {i} 行")))))
                .grow(1)
                .scroll_handle(list)
                .on_scroll(move |e: &ScrollEvent| far.set(e.offset[1] > 200.0)),
        )
        .child_when(move || far.get(), move || button("回到顶部").on_click(move || list.scroll_to(0.0, 0.0)))
}
```

## 拖动和叠放次序

```rust
/// 能拖的卡片：拖起来的那张升到最上面
pub fn stack() -> Element {
    let top = signal(0);
    let card = move |i: i32, color: Color| {
        let (x, y) = (signal(i as f32 * 60.0), signal(i as f32 * 30.0));
        let dragging = signal(false);
        rect()
            .size(140, 90)
            .radius(14)
            .background(color)
            .position(0, 0)
            .translation(x, y)
            .stack_order(move || if top.get() == i { 1 } else { 0 }) // 兄弟之间的叠放次序
            .cursor(move || if dragging.get() { Cursor::Grabbing } else { Cursor::Grab })
            .on_drag(move |e: &DragEvent| {
                dragging.set(matches!(e.phase, GesturePhase::Start | GesturePhase::Move));
                if e.phase == GesturePhase::Start {
                    top.set(i);
                }
                x.update(|x| *x += e.delta[0]);
                y.update(|y| *y += e.delta[1]);
            })
    };
    column().height(260).child(card(0, Color::hex(0xff375f))).child(card(1, Color::hex(0x0a84ff))).child(card(2, Color::hex(0x30d158)))
}
```

- 按下后移动超过 4 像素才开始拖（`GesturePhase::Start`），之后每次移动是 `Move`，松开是 `End`，窗口失去焦点时是 `Cancel`。开始后指针被这个元素捕获：移出元素、移出窗口都继续收到，这次按下不再算点击。
- `DragEvent` 里有 `delta`（和上一次的位移，各次加起来就是总位移）、`translation`（总位移）、`velocity`（最近约 0.1 秒的速度，逻辑像素每秒，松手时用来"甩出去"）、`start_position`、`position`、`window_position`、`button`、`modifiers`。
- 声明了平移动画的元素，拖动时用 `aureole::without_animation` 改位置（第 [8](08-动画.md) 章），否则每次移动都会被弹簧追着跑。
- `.stack_order(n)` 只在兄弟之间比较，大的画在上面、先被点到；相同的保持声明顺序。

右键菜单用浮层做（第 [12](12-浮层.md) 章）：

```rust
/// 右键菜单：浮层锚定在按下的那一点
pub fn canvas() -> Element {
    let (open, at) = (signal(false), signal([0.0f32, 0.0]));
    let menu = move || {
        column()
            .padding(4)
            .radius(6)
            .background(SURFACE)
            .border(1, LINE)
            .shadow(Shadow::new(0.0, 4.0, 12.0, Color::rgba(16, 24, 32, 0.18)))
            .child(text("在这里新建").padding_x(10).padding_y(6).on_click(move || open.set(false)))
    };
    column()
        .height(240)
        .radius(8)
        .background(SURFACE)
        .on_secondary_click(move |e: &ClickEvent| {
            at.set(e.window_position); // 窗口坐标；e.position 是元素自己的坐标
            open.set(true);
        })
        .overlay(
            open,
            Overlay::new(menu)
                .at(at) // 锚定在一点，靠近窗口边缘时翻过来
                .on_dismiss(move |_| open.set(false)),
        )
}
```

## 手势的仲裁：几个元素都想要时谁拿到

拖动、捏合、旋转开始时（拖动越过阈值、触控板手势开始），`Start` 走一遍捕获 → 目标 → 冒泡，决定谁拿到这个手势；之后的 `Move`、`End` 只交给拿到的元素。

| 处理器在 `Start` 里 | 结果 |
|---|---|
| `e.claim_gesture()` | 这个手势我要：这个元素拿到，传播到此为止。父元素在捕获阶段调用就是抢在里面的元素之前，里面的元素什么都收不到 |
| `e.decline_gesture()` | 不要：接着往外问，这个元素随后收到 `Cancel` |
| 不表态 | 目标和冒泡阶段第一个有 `on_drag` 的元素拿到（默认就是按下处最内层的那个）；在捕获阶段只看了一眼的元素收到 `Cancel` |
| `e.stop_propagation()` 又没有元素拿到 | 手势不开始：这次按下照常，松开算点击 |

**子元素让出**：列表里能横着拖的卡片，竖着的拖动让给外面的列表：

```rust
/// 列表里能横着拖的卡片：竖着的拖动让给外面的列表去滚动
pub fn swipe_cards() -> Element {
    let list = ScrollHandle::new();
    let card = move |name: String| {
        let x = signal(0.0f32);
        text(name.clone())
            .name(name)
            .height(56)
            .padding(16)
            .radius(8)
            .background(SURFACE)
            .border(1, LINE)
            .translation_x(x)
            .on_drag(move |e: &DragEvent| {
                // 只在 Start 表态：这里看的是越过阈值时的方向
                if e.phase == GesturePhase::Start && e.translation[1].abs() > e.translation[0].abs() {
                    e.decline_gesture(); // 不要：接着问外面的元素，这个元素随后收到 Cancel
                    return;
                }
                match e.phase {
                    GesturePhase::Start | GesturePhase::Move => x.update(|x| *x += e.delta[0]),
                    GesturePhase::End | GesturePhase::Cancel => x.set(0.0),
                }
            })
    };
    scroll_y(column().gap(8).padding(12).children((1..=20).map(move |i| card(format!("卡片{i}")))))
        .name("list")
        .height(300)
        .scroll_handle(list)
        .on_drag(move |e: &DragEvent| {
            let [x, y] = list.offset();
            list.jump_to(x, y - e.delta[1]); // 拖着内容走
        })
}
```

**父元素抢走**：能平移的画板，按住 Alt 时拖到节点上也是平移。在捕获阶段抢到的手势，之后的事件交给捕获阶段的处理器：

```rust
/// 能平移的画板：节点拖自己，空白处拖动平移；按住 Alt 时画板在捕获阶段抢走，拖到节点上也是平移
pub fn board() -> Element {
    let pan = signal([0.0f32; 2]);
    let node = signal([40.0f32, 40.0]);
    let move_by = |target: Signal<[f32; 2]>, e: &DragEvent| target.update(|p| *p = [p[0] + e.delta[0], p[1] + e.delta[1]]);
    rect()
        .name("board")
        .size(360, 240)
        .clip(true)
        .background(FILL)
        .on_drag(move |e: &DragEvent| move_by(pan, e)) // 没人要的拖动：最后问到这里
        .on_drag_capture(move |e: &DragEvent| {
            if e.phase == GesturePhase::Start && e.modifiers.has_alt() {
                e.claim_gesture(); // 抢在里面的元素之前：里面的元素这次什么都收不到
            }
            if e.phase == GesturePhase::Move {
                move_by(pan, e); // 抢到以后，Move、End 交给捕获阶段的这个处理器；没抢到时它只收到 Start 和 Cancel
            }
        })
        .child(
            rect()
                .name("node")
                .size(80, 48)
                .radius(6)
                .background(ACCENT_SOFT)
                .translation(move || pan.get()[0] + node.get()[0], move || pan.get()[1] + node.get()[1])
                .on_drag(move |e: &DragEvent| move_by(node, e)),
        )
}
```

- 手势只在开始时仲裁一次，拿到以后不能中途转给别的元素。要按方向分就在 `Start` 里看 `translation`（越过阈值时的方向）。
- 拖动交给外面的元素时，按下处它里面的元素当场收到 `on_press(false)` 和 `on_pointer_cancel`：画板里的按钮被拖过去时不会一直显示按下。
- 捏合、旋转一样（`on_pinch_capture`、`on_rotate_capture`）。

## 触摸屏

手指不用单独写：点按就是 `on_click`，拖动就是 `on_drag`，手指拖动滚动视口时视口自己滚（带惯性和回弹，和触控板同一份物理，主线程卡住时照样滑），长按和右键走同一个 `on_secondary_click`，两根手指走 `on_pinch`、`on_rotate`：

```rust
/// 能用手指（或者触控板）捏合、旋转的图片；长按（或者右键）弹菜单
pub fn photo() -> Element {
    let (zoom, angle) = (signal(1.0f32), signal(0.0f32));
    let (menu, menu_at) = (signal(false), signal([0.0f32; 2]));
    rect()
        .name("photo")
        .size(240, 160)
        .radius(8)
        .background(FILL)
        .scale(zoom)
        .rotation(move || rad(angle.get()))
        // 跟手：两个手势可以同时进行，各拿各的这一次的变化
        .on_pinch(move |e: &PinchEvent| zoom.update(|z| *z *= e.delta))
        .on_rotate(move |e: &RotateEvent| angle.update(|a| *a += e.delta.radians()))
        .on_secondary_click(move |e: &ClickEvent| {
            menu_at.set(e.window_position);
            menu.set(true);
        })
        .overlay(menu, Overlay::new(|| text("保存").name("menu").padding(8).background(SURFACE)).at(menu_at).on_dismiss(move |_| menu.set(false)))
}
```

和鼠标不一样的地方：

- **没有悬停**：手指放上时才进入（`on_hover(true)`），抬起后离开。别把只有悬停才看得到的按钮当成唯一的入口。
- **按下时还不知道手指要干什么**：拿焦点、放插入点等到点按完成（手指抬起）。`on_pointer_down`、`on_press` 还是按下时就发，手指滚起来时收到 `on_pointer_cancel`、`on_press(false)`，不会点击。所以按下就做事的控件放进列表要想清楚：想做按压反馈用 `on_press`，真的动作放 `on_click`。
- **阈值大一些**：移动 8 逻辑像素才算拖动（鼠标是 4）。
- **输入框**：点一下放插入点，拖动是滚内容，长按选词。
- 每根手指各走各的：第一根手指和鼠标走同一套；一根手指按着时另一根照样能点别的元素。事件上 `e.pointer_id` 分清是哪根手指，`e.device == PointerKind::Touch` 判断是不是手指。

手指拖动时谁拿到，和"手势的仲裁"是一回事，滚动视口只是又一个候选，排在它里面有 `on_drag` 的元素之后：列表里能横着拖的卡片（上面的 `swipe_cards`）竖着拖时 `decline_gesture()` 就轮到列表滚；不想让手指滚动时在 `on_pointer_down` 里 `e.prevent_builtin(Builtin::SCROLL)`，或者捕获指针。

长按的时长是平台惯例（`Conventions::long_press_duration`）。开发机没有触摸屏时用测试工具试：

```rust
/// 没有触摸屏也能测手指：第一个参数是手指的编号
pub fn touch_check() {
    let h = Harness::new(400.0, 300.0, photo());
    h.frame();
    let [x, y] = h.window_bounds("photo").expect("图片").center();
    // 两根手指张开：捏合
    h.touch_down(1, x - 40.0, y);
    h.touch_down(2, x + 40.0, y);
    for d in [50.0, 60.0, 70.0, 80.0] {
        h.touch_move(1, x - d, y);
        h.touch_move(2, x + d, y);
        h.frame();
    }
    h.touch_up(1);
    h.touch_up(2);
    let zoomed = h.window_bounds("photo").expect("图片");
    assert!(zoomed.width > 240.0, "放大了：{}", zoomed.width);
    // 一根手指按住不动：长按弹菜单
    h.touch_down(1, x, y);
    h.advance(aureole::Conventions::MACOS.long_press_duration + ms(50)); // 测试工具默认是 macOS 的惯例
    h.touch_up(1);
    assert!(h.bounds("menu").is_some(), "菜单开了");
    // 点外面关掉
    h.touch_tap(390.0, 290.0);
    h.advance(ms(100));
    assert!(h.bounds("menu").is_none(), "菜单关了");
}
```

## 键盘和焦点

```rust
pub fn keyboard_list() -> Element {
    let selected = signal(0usize);
    let items = ["苹果", "香蕉", "橙子"];
    column()
        .gap(4)
        .focusable(true) // 能获得焦点，按键从焦点往外冒泡
        .on_key_down(move |e: &KeyEvent| {
            if e.is("ArrowDown") {
                selected.update(|i| *i = (*i + 1).min(items.len() - 1));
                e.stop_propagation(); // 处理了，不再往外传
            }
            if e.is("ArrowUp") {
                selected.update(|i| *i = i.saturating_sub(1));
                e.stop_propagation();
            }
        })
        .children(items.into_iter().enumerate().map(move |(i, item)| {
            text(item)
                .padding(8)
                .radius(6)
                .background(move || if selected.get() == i { ACCENT_SOFT } else { Color::TRANSPARENT })
        }))
}
```

- `.focusable(true)` 让任何元素能获得焦点：Tab / Shift+Tab 按树的顺序走到它，指针按下也让它获得焦点；有焦点时**回车、空格触发它的 `on_click`**。输入框和基础控件天生能获得焦点。
- Tab 跳过禁用（`.disabled(true)`，自己或祖先）、看不见（透明度为 0、大小为 0）、正在退场的元素，到头绕回来；用键盘移到滚动视口外的元素时自动滚过去。
- **焦点环只画给键盘**：Tab、方向键带来的焦点画环，指针点的不画。`.focus_ring(FocusRing::new(颜色).width(..).offset(..))` 改样式，`FocusRing::NONE` 不画（元素自己用 `on_focus` 表现焦点时）。
- `.focus_arrows(Direction::Row)` / `Direction::Column`：方向键在子孙之间移动焦点（菜单、工具栏、列表）。
- `.disabled(..)` 让元素和子孙不响应点击、拖动、右键，不能获得焦点；外观由你自己表现（比如降低透明度，或者样式对象里的 `.disabled(..)` 状态）。基础控件禁用时自己变淡。
- `e.is("CmdOrCtrl+Enter")` 判断组合键，写法和快捷键一样。`KeyEvent` 里还有 `key`、`base`（不算修饰键时的按键）、`text`、`physical`（键位）、`modifiers`、`repeated`、`composing`（输入法正在组字）；`e.typed_text()` 是这个键要打出的字，`e.is_chord()` 是组合键（AltGr 不算），`e.has_primary_modifier()` 是平台的主修饰键（macOS 是 Command，别的平台是 Ctrl）。

```rust
/// ← → 在按钮之间移动焦点；焦点环换个样式
pub fn toolbar() -> Element {
    row()
        .gap(4)
        .focus_arrows(Direction::Row)
        .child(button("剪切"))
        .child(button("复制"))
        .child(button("粘贴"))
        .child(
            rect()
                .size(32, 32)
                .radius(8)
                .background(Color::hex(0xff9f0a))
                .focusable(true)
                .focus_ring(FocusRing::new(Color::WHITE).width(2.0).offset(3.0))
                .on_click(|| println!("自己画的按钮：Tab 走到后回车、空格也能触发")),
        )
}
```

### 按键的处理顺序

```text
按下一个键
 ├─ 原生菜单的快捷键（系统先处理，第 18 章）
 ├─ .preemptive(true) 的快捷键
 ├─ 捕获：on_key_down_capture，从外往里（能关的浮层在这里处理 Esc）
 ├─ 目标：焦点上你的 on_key_down，然后是输入框的编辑（编辑了就不往外传）
 ├─ 冒泡：on_key_down，从焦点往外，每个元素之后是它的 focus_arrows
 └─ 都没停止传播：快捷键 → 内置行为（Tab、回车和空格激活、方向键和翻页键滚动）
```

- 目标是有焦点的元素；没有焦点时是最上面的模态浮层的内容或第一个根元素。
- 输入框处理了的键（打字、⌘A、⌘C、方向键）不再往外传，所以同样的快捷键不触发；输入框不处理的组合键（Ctrl+K）照样往外走、触发快捷键。
- 输入法组字期间的按键交给输入法，不经过 `on_key_down`。

想在输入框之前截下按键（自动补全截下 ↑ ↓）用捕获阶段：

```rust
/// 自动补全：↑ ↓ 在输入框之前截下来选候选项，别的键照常进输入框
pub fn autocomplete() -> Element {

    column()

        .width(240)
        .on_key_down_capture(move |e| {
            if e.is("ArrowDown") {
                picked.update(|i| *i = (*i + 1).min(cities.len() - 1));

            } else if e.is("ArrowUp") {
                picked.update(|i| *i = i.saturating_sub(1));
                e.stop_propagation();
            }
        })
        .child(text_field(query).name("query").placeholder("城市").full_width(true))
        .children(cities.into_iter().enumerate().map(move |(i, city)| {
            text(city).padding_x(8).padding_y(4).radius(4).background(move || if picked.get() == i { ACCENT_SOFT } else { Color::TRANSPARENT })
        }))
        .child(text(move || cities[picked.get()].to_string()).name("picked").color(MUTED))
```

## 快捷键

```rust
pub fn shortcuts() -> Element {
    let count = signal(0);
    let search = FocusHandle::new();
    let query = signal(String::new());
    aureole::shortcut("CmdOrCtrl+K", move || search.focus()); // 归当前作用域：元素卸载时自动取消

}
```

- 写法：修饰键 `Cmd`（`Command`）、`Ctrl`、`CmdOrCtrl`（macOS 上是 Command，其他平台是 Ctrl）、`Alt`（`Option`）、`Shift`，按键是一个字符或 `Enter`、`Escape`、`Tab`、`Space`、`Backspace`、`Delete`、`ArrowUp`……、`Home`、`End`、`PageUp`、`PageDown`、`F1`～`F12`；加号写 `Plus`。写错时记一条警告（`tracing`），不生效。
- 快捷键归创建时的作用域所有，作用域释放时自动取消（也可以 `.cancel()`，或者 `.guard()` 收成守卫，守卫丢掉时取消，第 [26](26-插件和扩展点.md) 章）；在窗口里注册的只在这个窗口有焦点时生效。同一组合键注册了多个时最后注册的生效。
- **默认排在元素之后**：有焦点的元素处理了（停止传播）就收不到，输入框不会因为快捷键丢了复制粘贴。不管焦点在哪都要抢先的（命令面板、全局搜索）写 `.preemptive(true)`：

## 元素之间的拖放

```rust
/// 把任务拖进"已完成"：拖动的数据可以是任何类型，参数的类型决定谁接收
pub fn task_board() -> Element {
    let done = signal(Vec::<u32>::new());
    let over = signal(false);
    let task = |id: u32| {
        text(format!("任务 {id}"))
            .padding(10)
            .radius(6)
            .background(SURFACE)
            .border(1, LINE)
            .cursor(Cursor::Grab)
            .draggable(move || id) // 开始拖时调用一次，得到要拖的数据
    };
    row()
        .gap(16)
        .child(column().gap(8).child(task(1)).child(task(2)).child(task(3)))
        .child(
            column()
                .width(200)
                .height(160)
                .padding(10)
                .radius(10)
                .background(move || if over.get() { ACCENT_SOFT } else { FILL })
                .transition(Property::Background, Tween::new(ms(150)))
                .on_drag_enter(move |_: &DropEvent| over.set(true)) // 拖着它接收的数据进来
                .on_drag_leave(move || over.set(false)) // 离开、放下、取消都会调用
                .accepts_drop(move |id: &u32| !done.with(|d| d.contains(id))) // 再加个条件：已经完成的不接
                .on_drop(move |id: u32, _| done.update(|d| d.push(id))) // 参数的类型决定接收什么
                .child(text(move || format!("已完成：{:?}", done.get()))),
        )
}
```

- 拖动源：`.draggable(|| 数据)`，数据可以是任何类型（`'static`），越过 4 像素开始拖时调用一次。源元素自己的 `on_drag` 照常收到 `Start` / `Move`，被接住时是 `End`，没被接住（放在别处、Esc、窗口失去焦点）是 `Cancel`。
- 放置目标：`.on_drop(|数据: T, e| ..)`，**参数的类型决定接收什么**，可以有几个不同类型的；`.accepts_drop(|数据: &T| ..)` 再加条件。不接收的数据经过时没有任何事件，放下算取消。放在子元素上时交给最内层接收它的元素，源元素自己和子孙不算。
- `on_drag_enter` → `on_drag_over`（每次移动，滚动视口自动滚动时也有）→ `on_drag_leave`；放下时先 `on_drop` 再 `on_drag_leave`，所以高亮只要在离开时去掉。`DropEvent` 里有 `position`（目标自己的坐标）、`window_position`、`modifiers`，`e.data::<T>()` 看拖的是什么。
- 跟着指针的样子（`.drag_preview(..)`）：默认 `DragPreview::Copy`，一份半透明的拷贝浮在最上面，原来的元素变淡；放下后元素还在的话拷贝落到它的新位置，取消时飞回去。`DragPreview::Lift` 是元素自己跟着走（画在兄弟上面，会被祖先裁剪，适合同一个列表里排序），`DragPreview::None` 自己画。拖的时候只动合成层，不重新布局、不重画。
- 在一行或一列里排序时，`.drag_preview_axis(Direction::Row)`（横着的标签条）或 `Direction::Column`（竖着的列表）让跟着指针的样子只沿这个方向走，`.drag_preview_contained(true)` 让它碰到父元素的边就停住，不被裁剪的父元素挡掉一半。这两项只管样子，找放置目标还是看指针在哪。
- 指针靠近滚动视口的边缘时自动滚动，越近越快；拖动时普通的悬停（`on_hover`）不变，放置目标用进入、离开表现。

列表算"插在第几项"用经过事件的位置：

```rust
/// 列表算插在第几项：经过事件的位置是目标自己的坐标；插入线在合成层上滑过去
pub fn insertion() -> Element {
    let at = signal(None::<usize>);
    let rows = ["一", "二", "三"];
    column()
        .width(220)
        .gap(8)
        .children(rows.map(|r| text(r).height(32).padding_x(10).radius(6).background(SURFACE)))
        .child(
            rect()
                .position(0, 0)
                .size(220, 2)
                .background(ACCENT)
                .translation_y(move || at.get().map_or(0.0, |i| i as f32 * 40.0 - 5.0))
                .transition(Property::TranslationY, Spring::snappy())
                .opacity(move || if at.get().is_some() { 1.0 } else { 0.0 }),
        )
        .on_drag_over(move |e: &DropEvent| at.set(Some(((e.position[1] + 20.0) / 40.0).floor().clamp(0.0, 3.0) as usize)))
        .on_drag_leave(move || at.set(None))
        .on_drop(move |text: String, _| println!("把「{text}」插在第 {} 项", at.get().unwrap_or(0)))
}
```

## 能拖动排序的列表

```rust
/// 能拖动排序的列表：拖起一行，别的行平滑让开；有焦点的行按 ⌥↑ ⌥↓ 也能移动
pub fn sortable() -> Element {
    let tasks = signal(vec!["写周报", "改设计稿", "回邮件", "订会议室"]);
    let list = reorderable(tasks, |t: &&str| *t, |t: &str| {
        row()
            .height(36)
            .padding_x(10)
            .radius(6)
            .align(Align::Center)
            .background(SURFACE)
            .border(1, LINE)
            .child(text(t))
    })
    .gap(6.0)
    .on_reorder(|from, to| println!("第 {from} 项移到第 {to} 项")) // tasks 已经改好了
    .build();
    scroll_y(list).height(200) // 拖到视口边缘自动滚动
}
```

`reorderable(列表信号, key, 每一项的视图)` 按住一行拖动就能换位置，放下时直接改信号里的顺序。行都在合成层上：拖的时候别的行用临界阻尼的弹簧让开，被拖的行跟着指针，松手后落到新位置，全程不重新布局。行可以不一样高。**键盘也能排**：行能获得焦点（↑ ↓ 在行之间移动），有焦点的行按 ⌥↑ / ⌥↓ 上下移一格。`.report_dragging(信号)` 拿到正在被拖的那一行，用来换成"浮起来"的样子。拖的数据是这一行的 key，别的目标（比如回收站）用 `on_drop(|key: K, _| ..)` 也能接。

## 拖到应用外面

```rust
/// 拖到访达：文件要已经存在；拖到文本编辑器里的用 `DragOut::text`
pub fn export_file() -> Element {
    let path = std::env::temp_dir().join("导出.txt");
    let _ = std::fs::write(&path, "拖出去的内容");
    text("导出.txt（拖到访达）")
        .padding(10)
        .cursor(Cursor::Grab)
        .drag_out(move || DragOut::file(path.clone()))
        .on_drag_out_end(|copied| println!("访达{}", if copied { "拷贝了一份" } else { "没有接收" }))
}
```

- `.drag_out(|| DragOut::file(路径))` / `DragOut::files(..)` / `DragOut::text(..)`：越过 4 像素时交给系统开始拖（macOS 的拖动会话，拖动的图像是文件或文字的系统图标），这次按下到此为止，松开不算点击。访达里只会拷贝，不会把原文件挪走。
- 同时是 `.draggable(..)` 时先在应用里拖，拖出窗口时才交给系统（应用里的拖放取消）。
- `on_drag_out_end(|接住了| ..)` 在系统的会话结束时调用。目前只有 macOS 实现了，其他平台上什么都不做，收到 `false`。

## 按键松开

```rust
/// 按住空格时平移：按下、松开成对，按住期间焦点换了、窗口失去焦点也不会卡住
pub fn hold_space() -> Element {
    let panning = signal(false);
    aureole::key_up_listener(|e: &KeyEvent| println!("松开了 {:?}", e.key)); // 窗口的：元素都没停止传播的松开
    rect()
        .size(240, 140)
        .radius(10)
        .background(move || if panning.get() { ACCENT_SOFT } else { FILL })
        .transition(Property::Background, Tween::new(ms(120)))
        .focusable(true)
        .on_key_down(move |e: &KeyEvent| {
            if e.is("Space") {
                panning.set(true);
                e.stop_propagation();
            }
        })
        .on_key_up(move |e: &KeyEvent| {
            if e.is("Space") {
                panning.set(false);
                e.stop_propagation();
            }
        })
        .cursor(move || if panning.get() { Cursor::Grabbing } else { Cursor::Default })
}
```

- `.on_key_up(..)` 和 `on_key_down` 一样走捕获、目标、冒泡，停止传播就不再往外传；都没停止时交给窗口的 `aureole::key_up_listener(..)`（归当前作用域，像快捷键一样）。
- 松开总是交给**按下时**的那条路径：按住期间焦点换了、对话框打开了，按下时的元素照样收到松开；窗口失去焦点（切到别的应用）、输入法开始组字时，按着的键当场松开。按下交给了输入法的键，松开也不交出来。事件里的按键和按下时一样，修饰键是松开时的。
- `aureole::is_key_down("Space")` 问这个键现在是不是按着（不订阅，按键时读一下很便宜）。
- 测试工具里 `h.key_down(..)` 只按下，`h.key_up(..)` / `h.key_up_with(..)` 松开，`h.unfocus_window()` 模拟窗口失去焦点。

## 坑

- **收事件对象的闭包要写参数的类型**：`.on_drag(|e: &DragEvent| ..)`，写成 `|e|` 时编译器报 `type annotations needed`（见上面"处理器的写法"）。
- **点击默认冒泡**：外层也有 `on_click` 时，里面处理完要不要让外面也收到，自己决定（`e.stop_propagation()`）。基础控件替你停了，自己拼的可点击元素没有。
- **指针的停止传播不取消内置行为**：`stop_propagation` 之后焦点、选字、拖动照常，要取消用 `prevent_builtin`。按键相反，停止传播以后内置行为也不做了。
- 不要用 `CmdOrCtrl+C/V/X/A/Z` 注册快捷键或菜单快捷键：菜单先于窗口收到按键，会抢走输入框的复制、粘贴、全选、撤销。
- `on_drag_capture` 在没抢到时也收到 `Start` 和 `Cancel`：只处理自己抢到以后的事件，别把 `Start` 里的位移当成自己的。
- 拖动的元素如果声明了平移动画，拖的时候记得 `without_animation`。
- 拖着指针出了窗口时，系统按自己的规则显示指针，不是被拖元素的形状。
- `stack_order` 只在兄弟之间比较；跨层级"提到最上面"用浮层。
- 子元素超出父元素范围的部分点不到，不管父元素裁不裁剪。
- 输入法组字期间的按键交给输入法，不经过 `on_key_down`，松开也不经过 `on_key_up`。
- 拖放的影子是源元素此刻的样子再画一遍：拖的时候源元素变了（文字、颜色），影子也跟着变，所以别在 `on_drag` 里改源元素的样子来表示"被拖走了"（框架已经让它变淡）。不想要拷贝时用 `DragPreview::Lift` 或 `DragPreview::None`。
- `DragPreview::Lift` 的元素还在原来的父元素里，会被祖先（滚动视口、裁剪）挡住；只在父元素里排序时加 `drag_preview_contained(true)`，要拖到别的容器里用默认的 `Copy`。
- 元素之间的拖放能拖到应用的另一个窗口（交给系统的拖放，数据留在进程里），那边的元素照常 `on_drop`；源元素的 `on_drag` 这时收到 `Cancel`，有没有被接住看 `on_drag_out_end`。别的窗口里没有影子，显示系统的拖动图像；Linux 上拖不出窗口。
- 列表里能拖放的行（`draggable`）手指一拖就是拖放，外面的列表滚不动：要滚就留出行以外的地方，或者竖着的拖动 `decline_gesture()`。
- 手指滚起来以后不会再有 `on_pointer_up`：按下时开始的事情要在 `on_pointer_cancel` 里收尾。
