# 18. 多窗口、菜单栏、托盘、拖放文件、定时器

本章的导入：

```rust
use std::path::PathBuf;
use aureole::prelude::*;
use aureole::{Menu, MenuItem, Submenu, TitleBar, Tray, WindowMaterial, title_bar_info};
```

## 多窗口

所有窗口在同一个主线程、同一个响应式运行时里，**窗口之间通信就是共享信号**：一个窗口改了信号，另一个窗口里绑定它的属性自动更新。

```rust
pub fn open_counter(count: Signal<i32>) -> WindowHandle {
    Window::new(move || {
        let me = current_window().expect("在窗口里构建");
        column()
            .padding(24)
            .gap(12)
            .child(text(move || format!("共享计数：{}", count.get())).font_size(20))
            .child(text(move || {
                let [w, h] = me.size(); // 窗口状态是响应式的
                format!("窗口 {w:.0} x {h:.0}")
            }))
            .child(button("+1").on_click(move || count.update(|c| *c += 1)))
            .child(button("关闭这个窗口").on_click(move || me.close()))
    })
    .title(move || format!("计数 {}", count.get())) // 标题可以绑定
    .size(320, 240)
    .always_on_top(true)
    .open() // 下一轮事件循环创建；句柄马上能用
}
```

- `Window::new(构建视图)` 的设置：`.title(..)`（可以绑定）、`.size(w, h)`、`.position(x, y)`、`.min_size(..)`、`.resizable(..)`、`.always_on_top(..)`、`.fullscreen(..)`、`.decorations(..)`（有无标题栏和边框）、`.background(..)`、`.on_close_request(|e| ..)`（不让关时调 `e.prevent_builtin(Builtin::CLOSE)`），最后 `.open()`。在任何地方都能调用（处理器、定时器里）。
- `WindowHandle` 像信号一样是 `Copy` 的。读状态的方法是**响应式**的：`size()`、`position()`、`is_focused()`、`is_fullscreen()`、`is_minimized()`、`is_maximized()`、`is_open()`；操作：`close()`、`focus()`、`set_title(..)`、`set_size(..)`、`set_position(..)`、`set_fullscreen(..)`、`set_always_on_top(..)`、`set_minimized(..)`、`set_maximized(..)`。
- `current_window()` 是正在构建视图、处理事件的那个窗口（子窗口里的"关闭"按钮用它关掉自己）；测试工具里是 `None`。
- `aureole::quit()` 关闭所有窗口、退出应用。默认关掉最后一个窗口时退出；只有托盘的应用用 `App::quits_on_last_window_closed(false)`。

```rust
pub fn window_info() -> Element {
    let me = current_window(); // 测试工具里没有窗口，是 None
    let info = move || match me {
        Some(w) => {
            let ([width, height], [x, y]) = (w.size(), w.position());
            format!("{width:.0} x {height:.0}，在 ({x:.0}, {y:.0})，{}", if w.is_focused() { "有焦点" } else { "没有焦点" })
        }
        None => "没有窗口".to_string(),
    };
    column().gap(8).align(Align::Start).child(text(info)).child(button("全屏").on_click(move || {
        if let Some(w) = me {
            w.set_fullscreen(!w.is_fullscreen());
        }
    }))
}
```

## 菜单栏和托盘

在 `menus` 特性后面，默认开。不要菜单栏和托盘的应用可以关掉（`default-features = false`），少三个库、约半兆；关掉时这些 API 不存在。平台支不支持用 `aureole::capabilities()` 问（`supports_menu_bar`、`supports_tray`）：Linux 没有菜单栏。

```rust
pub fn main() {
    let count = signal(0); // 所有窗口共享：一个窗口改了，另一个窗口跟着变
    let dirty = signal(false);
    let on_top = signal(false);
    App::new(move || {
        if let Some(me) = current_window() {
            Effect::new(move || me.set_always_on_top(on_top.get())); // 菜单里的勾选项 → 窗口
        }
        column()
            .padding(24)
            .gap(12)
            .align(Align::Start)
            .child(text(move || format!("计数：{}", count.get())))
            .child(button("打开新窗口").on_click(move || {
                open_counter(count);
            }))
            .child(Switch::new(dirty).label("有没保存的修改（开着时关不掉窗口）"))
    })
    .title("多窗口")
    .size(480, 360)
    .menu(menu(count, on_top))
    .tray(tray(count))
    .window(move |w| w.min_size(400, 300).on_close_request(move |e| {
        if dirty.get() {
            e.prevent_builtin(Builtin::CLOSE);
        }
    }))
    .run();
}

fn menu(count: Signal<i32>, on_top: Signal<bool>) -> Menu {
    Menu::new()
        .submenu(Submenu::app("我的应用")) // 关于、隐藏、退出……
        .submenu(
            Submenu::new("窗口")
                .item(MenuItem::new("新建窗口").shortcut("CmdOrCtrl+N").on_click(move || {
                    open_counter(count);
                }))
                .separator()
                .item(MenuItem::new("置顶").checked(on_top)), // 勾选和信号双向同步
        )
        .submenu(
            Submenu::new("计数")
                .item(MenuItem::new(move || format!("现在是 {}", count.get())).disabled(true)) // 文字绑定信号
                .item(MenuItem::new("清零").disabled(move || count.get() == 0).on_click(move || count.set(0))),
        )
}

fn tray(count: Signal<i32>) -> Tray {
    Tray::new()
        .icon_stroke(VectorPath::svg("M3 8 H15 V20 H3 Z M9 3 H21 V15 H17").view_box(0.0, 0.0, 24.0, 24.0), Stroke::new(1.8).round())
        .tooltip("我的应用")
        .title(move || count.get().to_string()) // macOS 菜单栏里图标旁边的文字
        .menu(Menu::new().item(MenuItem::new("+1").on_click(move || count.update(|c| *c += 1))).separator().item(MenuItem::new("退出").on_click(aureole::quit)))
}
```

- `App::menu(..)` 设置原生菜单栏（macOS 屏幕顶部，Windows 窗口标题栏下面；Linux 上不显示，但菜单项的快捷键照样起作用）；`App::window(|w| ..)` 对主窗口做更多设置。
- 菜单项的文字、禁用（`.disabled(..)`）、是否打勾（`.checked(信号)`，点击时切换信号）都能绑定，状态变了菜单跟着变。闭包在主线程、在创建菜单时的作用域里执行，和处理器一样。
- macOS 把菜单栏的第一项当作应用菜单：`Submenu::app(名字)` 有关于、服务、隐藏、退出这些系统项（按用户的语言显示）；第一项不是它时自动补上。应用名打包后用 Info.plist 里的名字，没打包时用主窗口的标题。Windows 上 `Submenu::app` 只有"关于"、自己加的项和"退出"。
- 托盘图标用矢量路径画（`.icon(路径)` 填充、`.icon_stroke(路径, 描边)` 描边），macOS 上跟着菜单栏的深浅色变，Windows、Linux 上按任务栏 / 面板的深浅画成白色或深色。只有菜单时左键弹菜单；同时有 `.on_click(..)` 时左键调用它、右键弹菜单。
- Linux 的托盘走 StatusNotifierItem：KDE、Xfce、Cinnamon 直接显示，GNOME 要装 AppIndicator 扩展（Ubuntu 默认有）；桌面不支持时托盘不显示，记一条错误。

## 自己画标题栏、窗口材质

`.title_bar(TitleBar::Hidden)` 让内容铺满整个窗口，标题栏由你自己画；`.backdrop(WindowMaterial::…)` 让窗口背后透出系统的材质。

```rust
pub fn title_bar() -> Element {
    let query = signal(String::new());
    let me = current_window();
    column()
        .child(
            row()
                .window_drag_area(true) // 按住拖动窗口，双击按系统设置缩放
                .height(move || px(title_bar_info().height.max(38.0))) // 系统给的高度，绑定了就跟着变
                .align(Align::Center)
                .gap(8)
                .child(text("笔记").margin_left(move || px(title_bar_info().inset_left.max(12.0)))) // 给红绿灯让开
                .child(rect().grow(1.0))
                .child(text_field(query).width(160)) // 里面的输入框、按钮照常响应，按在它们上面不拖窗口
                .child(button("分享"))
                // 系统不留窗口按钮的平台（Windows、Linux）自己画
                .child_when(move || title_bar_info().controls.is_none(), move || maximize_button(me)),
        )
        .child(text("正文").padding(16))
}

fn maximize_button(me: Option<WindowHandle>) -> Element {
    button("□")
        .window_maximize_button(true) // Windows 11 上悬停时弹出贴靠布局
        .on_click(move || {
            if let Some(w) = me {
                w.set_maximized(!w.is_maximized());
            }
        })
}

pub fn open_notes() {
    Window::new(title_bar)
        .title("笔记") // 不显示，任务切换和读屏软件还用它
        .title_bar(TitleBar::Hidden)
        .title_bar_controls_position(14, 12) // macOS 的红绿灯放在哪
        .backdrop(WindowMaterial::Sidebar) // 窗口背后透出系统的材质
        .open();
}
```

- **拖动窗口**：元素上 `.window_drag_area(true)`。按住拖动窗口，双击按系统设置缩放或最小化。里面能接按下的元素（有点击处理器的、按钮、输入框）照常响应，按在它们上面不拖；子元素设 `false` 挖一块；处理器里 `e.prevent_builtin(Builtin::WINDOW_DRAG)` 取消一次。按在拖动区域上不动焦点，和按在系统的标题栏上一样。
- **标题栏占了多少**：`title_bar_info()` 是响应式的，窗口缩放、进出全屏时跟着变，直接绑到布局上：`height` 是高度，`controls` 是系统窗口按钮的范围（要自己画按钮的平台是 `None`），`inset_left`、`inset_right` 是内容要让开多少。全屏时都是 0。别的窗口的用 `WindowHandle::title_bar_info()` 读。
- **窗口按钮**：macOS 留着红绿灯（`.title_bar_controls_position(x, y)` 挪位置，窗口缩放、进出全屏后保持）；Windows、Linux 要自己画，最小化、最大化、关闭分别调 `WindowHandle` 的 `set_minimized`、`set_maximized`、`close`。最大化按钮设 `.window_maximize_button(true)`，Windows 11 上悬停时弹出贴靠布局。
- **材质**：`Window`（主窗口的底）、`Sidebar`（侧栏）、`Header`（顶部一条）、`Menu`、`Popover`。设了以后窗口清屏成透明，元素没盖住的地方透出后面的东西，半透明的元素（`Color::WHITE.with_alpha(0.5)`）盖在材质上。窗口失去焦点时的样子跟系统。`WindowHandle::set_backdrop(..)` 换材质（Windows 上打开窗口时没有设的，之后设不上）。
- 能不能用查 `aureole::capabilities()`：`supports_hidden_title_bar`、`supports_title_bar_controls`（系统留着窗口按钮）、`supports_snap_layouts`、`supports_window_backdrop`。没有窗口材质的平台照常画不透明的背景，所以界面不要靠透出来的东西才看得清。

测试里没有窗口：`Harness::window_drag_count()`、`title_bar_double_click_count()`、`maximize_button_area()` 读交给窗口的请求，`Harness::set_title_bar_info(..)` 模拟度量。

## 拖放文件和别的内容

```rust
pub fn drop_zone() -> Element {
    let hovering = signal(false);
    let files = signal(Vec::<PathBuf>::new());
    column()
        .height(120)
        .padding(16)
        .radius(12)
        .border(2, move || if hovering.get() { ACCENT } else { LINE })
        .transition(Property::BorderColor, Tween::new(ms(150)))
        .on_file_hover(move |inside| hovering.set(inside)) // 拖着文件进来、出去
        .on_file_drop(move |e: &FileDropEvent| files.update(|f| f.extend(e.paths.iter().cloned()))) // 放下
        .child(text(move || format!("拖进来 {} 个文件", files.with(Vec::len))))
}
```

文件交给指针下最内层有 `on_file_drop` 的元素；一次拖进来几个文件，攒在一起交出去。

放下的只要文件时用上面两个就够了。要接别的应用拖来的文字、链接、图片，用 `on_external_*`：

```rust
pub fn external_drop_zone() -> Element {
    let hovering = signal(false);
    let received = signal(String::new());
    column()
        .height(120)
        .padding(16)
        .radius(12)
        .border(2, move || if hovering.get() { ACCENT } else { LINE })
        .on_external_drag_over(move |e: &ExternalDragEvent| {
            // 拖着的时候只知道有哪几种：这里不接文件
            if e.kinds.intersects(ExternalDataKinds::TEXT | ExternalDataKinds::LINK | ExternalDataKinds::IMAGE) {
                e.accept(); // 系统显示能放下的光标；不调用就接着问外面一层的元素
                hovering.set(true);
            }
        })
        .on_external_drag_leave(move || hovering.set(false))
        .on_external_drop(move |e: &ExternalDropEvent| {
            let mut got = Vec::new();
            got.extend(e.text.iter().map(|text| format!("文字：{text}")));
            got.extend(e.link.iter().map(|link| format!("链接：{link}")));
            got.extend(e.image.iter().map(|image| format!("图片：{}×{}", image.width, image.height)));
            received.set(got.join("\n"));
        })
        .child(text(move || if received.with(String::is_empty) { "从别的应用拖文字、链接、图片到这里".to_string() } else { received.get() }))
}
```

- `on_external_drag_over`：拖着经过时调用，`e.kinds` 是内容有哪几种，这时读不到内容。调用 `e.accept()` 才算接受，系统显示能放下的光标；`e.accept_with(ExternalDropEffect::Link)` 说明算什么操作（光标不一样）。不调用就接着问外面一层的元素。
- `on_external_drag_leave`：离开、取消、放下之后。
- `on_external_drop`：放下，`e.text`、`e.link`、`e.image`（`RgbaImage`，能直接给 `image()`）、`e.files`、`e.position`。只有它、没有 `on_external_drag_over` 的元素什么都接受。
- 文件也走这组事件（种类是 `ExternalDataKinds::FILES`），和 `on_file_hover`、`on_file_drop` 互不影响。
- macOS、Windows 都支持。Linux 上窗口库只提供文件，`aureole::capabilities().supports_external_drop` 是假，这组事件只收得到文件。
- 测试工具里用 `h.external_drag_over(x, y, 种类)`（返回元素的回答）、`h.external_drop(x, y, 内容)`。

## 定时器

```rust
pub fn clock() -> Element {
    let seconds = signal(0);
    let hint = signal(true);
    aureole::every(secs(1), move || seconds.update(|s| *s += 1)); // 元素卸载时自动取消
    aureole::after(secs(3), move || hint.set(false));
    column()
        .gap(4)
        .child(text(move || format!("已运行 {} 秒", seconds.get())).tabular_numbers(true))
        .child_when(move || hint.get(), || text("这行字三秒后消失"))
}
```

`aureole::after(延迟, f)` 执行一次，`aureole::every(间隔, f)` 一直执行；`f` 在主线程、在创建时的作用域里执行，作用域释放（元素卸载、窗口关闭）时自动取消，丢掉句柄不影响它；也可以 `.cancel()`，或者 `.guard()` 收成守卫（第 [26](26-插件和扩展点.md) 章）。精度大约是事件循环的一轮；没有定时器到期时事件循环一直睡，不耗电。

## 坑

- 隐藏了标题栏的窗口（Windows）不挂菜单栏：菜单栏长在系统的标题栏下面。窗口里要可见的菜单用第 [12](12-浮层.md) 章的下拉菜单做。
- 菜单的快捷键先于窗口收到按键，所以默认没有"编辑"菜单（复制粘贴由输入框自己处理），也不要用 `CmdOrCtrl+C/V/X/A/Z` 当菜单快捷键。
- Linux 上不显示菜单栏（窗口里要可见的菜单，用第 [12](12-浮层.md) 章的下拉菜单做），菜单项的快捷键照样起作用；Windows、Linux 上托盘图标不显示文字（`.title(..)` 只有 macOS 显示）。
- `WindowHandle::close()` 不经过 `on_close_request`，只有用户点关闭按钮时才问。
- 关窗口时这个窗口的作用域连同里面的信号、定时器、任务一起释放；窗口关了以后读它的状态仍然安全（读到最后的值）。
