# 23. 打包与发布

## `cargo bundle`

框架带了一个打包工具，macOS 上打成 .app，Windows、Linux 上打安装包（见下面"Windows、Linux 的安装包"）。macOS 上：编译、Info.plist、图标、临时签名，可选做成 .dmg。在框架的工作区里 `cargo bundle` 是现成的别名：

```bash
cargo bundle --release          # → target/release/bundle/应用名.app，临时签名
cargo bundle --release --dmg    # 再做一个 .dmg（打开后拖进"应用程序"）
cargo bundle --help             # 全部选项
```

先把打包工具装成 cargo 的子命令，之后在任何项目里都能用 `cargo bundle`：

```bash
cargo install aureole-bundle --version 0.0.1-beta.3
```

它在当前目录读包的设置、编译。工作区只有一个包时不用写 `-p`，也不用先写打包设置：名字、标识符、图标都有默认值。已经装过同名命令的话，`cargo install` 要加 `--force`。

## 设置

写在应用的 `Cargo.toml` 里，命令行参数（`--name`、`--id`、`--version`、`--icon`、`--target`、`--out`、`--sign`、`--no-sign`……）优先：

```toml
[package.metadata.bundle]
name = "待办"                            # 应用名：访达、程序坞、菜单栏里显示，可以是中文
identifier = "com.example.todo"          # 包标识符，系统通知要用
category = "productivity"                # 应用分类
copyright = "© 2026 我"
minimum-system-version = "11.0"          # 默认 11.0
resources = ["assets"]                   # 拷进 Contents/Resources
info-plist = { LSUIElement = true }      # 原样写进 Info.plist（这里：只有托盘、不进程序坞）
url-schemes = ["todo"]                   # 能打开 todo://…（App::on_open 接收）
# 能打开的文档：没写 uti 的是应用自己的类型（导出类型声明、默认用这个应用打开），写了 uti 的是系统已有的类型（只进"打开方式"）
document-types = [
    { name = "待办清单", extensions = ["todolist"], role = "editor", icon = "assets/list.png" },
    { name = "Markdown", extensions = ["md"], uti = "net.daringfireball.markdown", mime = "text/markdown" },
]
# 图标：矢量（下面这样），或者图片：icon = "assets/icon.png"（方形 PNG，建议 1024x1024；也可以是现成的 .icns）
icon = { path = "M5 12.5 L10 17.5 L19.5 7", view-box = [0, 0, 24, 24], stroke = 2.8, background = ["#4cd964", "#16904a"] }
```

- **矢量图标**：SVG 路径语法，`view-box` 是画布，`stroke` 是描边宽度（不写就填充），`background` 是一个颜色或上下渐变，`foreground` 默认白色。按系统图标的版式画：圆角方块、渐变、投影，图形放在中央、占方块的一半；16 到 1024 每个尺寸都重新栅格化。先看效果：`cargo bundle -p 包名 --icon-preview icon.png`。
- **Info.plist**：包标识符、显示名、版本、最低系统版本、分类、高分辨率支持都会写好；`info-plist` 表里的键原样写进去、覆盖同名的键（用摄像头时写 `NSCameraUsageDescription`）。
- **签名**：默认临时签名（`codesign -s -`），本机运行没问题（发系统通知要看系统：macOS 27 上临时签名的包被拒绝了通知权限，日志里有系统说的原因），打包后自动 `codesign --verify` 检查。临时签名只在本机有效：发给别人的应用要用自己的开发者证书签名（`--sign "Developer ID Application: …"`，`entitlements = "app.entitlements"` 传给 codesign），再自己做公证（工具不做公证、不连接任何外部服务）。
- 系统通知只有打包后才能发：第一次发时系统请求权限。
- 打包后的应用菜单里，"关于""退出"带上 Info.plist 里的应用名。
- **协议和文档类型**：`url-schemes` 生成 `CFBundleURLTypes`；`document-types` 生成 `CFBundleDocumentTypes`，应用自己的类型再生成 `UTExportedTypeDeclarations`（标识是 `包标识符.扩展名`）。`role` 是 `editor` / `viewer`（默认）/ `shell` / `none`，`rank` 默认自己的类型是 `owner`、系统的类型是 `alternate`（不改用户的默认应用）。`icon` 是文档图标（PNG 或 .icns）。系统第一次看到这个 .app（打开它、或者它在"应用程序"文件夹里）时登记这些声明。不要占用 `http`、`file` 这些系统常用的协议（打包时报错）。

## Windows、Linux 的安装包

安装包要在目标系统上打，交给外部工具 cargo-packager，先装一次：

```bash
cargo install cargo-packager --version 0.11.8 --locked
```

设置还是写在上面那个 `[package.metadata.bundle]` 里，不用另写一份：

```bash
cargo bundle --release                       # Windows：todo_0.1.0_x64-setup.exe
cargo bundle --release                       # Linux：todo_0.1.0_amd64.deb、todo_0.1.0_x86_64.AppImage
cargo bundle --release --format deb          # 只要其中一种
```

- **Windows**：装给当前用户，不要管理员权限，开始菜单的快捷方式带应用标识，系统通知能用。`/S` 静默安装。发布版不想要控制台窗口，在 `main.rs` 开头写 `#![cfg_attr(all(windows, not(debug_assertions)), windows_subsystem = "windows")]`。
- **Linux**：.deb 里有图标、`.desktop`、依赖，协议和文档类型在安装时登记好。依赖不够时用 `linux-depends = ["libfoo1"]` 加。维护者写 `maintainer = "名字 <邮箱>"`。AppImage 加上执行权限就能运行。

### 换 NSIS 安装程序的图片和模板

```toml
[package.metadata.bundle.nsis]
sidebar-image = "packaging/side.png"   # 什么常见格式都行，工具换成 NSIS 要的 BMP
header-image = "packaging/head.png"
installer-icon = "packaging/setup.png"
template = "packaging/setup.nsi"       # 自己的 NSIS 脚本，页面、流程都能改
```



## 用 Aureole 写安装程序

想要和应用一样的界面时，用框架自己画安装程序。不写代码也能用，默认是一个向导：

```bash
cargo bundle --release --format installer   # 在 Windows、Linux 上，不用装 cargo-packager，应用也不用加依赖
```

解压、校验、回滚、升级、卸载、快捷方式、"应用和功能"里的卸载项、协议、文档类型都做好了。装给当前用户，不要管理员权限。`--silent` 不开窗口，`--dir 目录` 指定目录。

要换样子时写一个小程序，在应用的 `Cargo.toml` 里指定它：

```toml
[package.metadata.bundle.installer]
package = "my-setup"
```

向导能换颜色、图片、文字、协议，能加页：

```rust
/// 向导：换颜色、一句话、协议，加一页自己的选项
fn wizard(session: Session, wanted: Arc<AtomicBool>) -> Element {
    Wizard::new()
        .accent(ACCENT)
        .tagline("换了颜色和文字的向导")
        .license(LICENSE)
        .page(move |_| {
            let choice = signal(wanted.load(Ordering::Relaxed));
            let wanted = wanted.clone();
            aureole::effect(move || wanted.store(choice.get(), Ordering::Relaxed));
            column().gap(12).child(text("选择组件").font_size(20)).child(checkbox(choice).label("同时装示例文件"))
        })
        .build(session)
}

fn run(setup: Setup) -> ExitCode {
    let wanted = Arc::new(AtomicBool::new(true));
    let for_step = wanted.clone();
    setup.step(move || WriteSampleFiles { wanted: for_step.clone() }).run(move |session| wizard(session, wanted))
}
```

少见的需求（注册服务、装驱动、改防火墙、先装依赖）写一个 `Step`。它在文件都就位之后运行，失败时跟着回滚，卸载时也会调用：

```rust
/// 自定义的一步：内置的都没有的事（注册服务、装驱动、改防火墙……）。
/// 在解压和系统集成之后运行，失败时跟着回滚，卸载时调用 `remove`
struct WriteSampleFiles {
    /// 自己加的那一页上的选项：界面在主线程，步骤在后台线程，用原子量传
    wanted: Arc<AtomicBool>,
}

impl Step for WriteSampleFiles {
    fn name(&self) -> &str {
        "写示例文件"
    }

    fn apply(&mut self, cx: &StepContext) -> Result<(), String> {
        // 走慢一点，看得到进度
        std::thread::sleep(Duration::from_millis(800));
        if self.wanted.load(Ordering::Relaxed) {
            std::fs::write(cx.directory.join("示例.txt"), "这是安装时写的").map_err(|e| e.to_string())?;
        }
        Ok(())
    }

    fn remove(&mut self, cx: &StepContext) -> Result<(), String> {
        let _ = std::fs::remove_file(cx.directory.join("示例.txt"));
        Ok(())
    }
}
```

界面完全自己画时不用 `Wizard`，传一个 `fn(Session) -> Element`。`Session` 就是向导用的全部接口：

| 接口 | 作用 |
|---|---|
| `manifest()`、`mode()`、`size_text()` | 应用名、版本、发布者；安装还是卸载；要多少空间 |
| `directory()`、`menu_shortcut()`、`desktop_shortcut()`、`launch_after()` | 选项，都是信号 |
| `state()`、`progress()`、`previous_version()` | 进行到哪了，进度，已经装的版本 |
| `choose_directory()`、`start()`、`cancel()`、`launch()`、`finish()` | 操作。失败、取消之后再 `start()` 就是重试 |

写界面时不用打包：`Setup::new().package(Package::preview(清单))` 用一个假的包走一遍，只写你指定的目录，不碰系统。

安装程序带着框架，比 NSIS 大（`todo` 在 Windows 上：22.3 MB 对 7 MB），不在乎界面时用 NSIS、.deb 更合适。

## macOS 的通用二进制

同一个 .app 在 Apple 芯片和 Intel 的 Mac 上都能原生运行，体积差不多是两倍：

```bash
rustup target add x86_64-apple-darwin
cargo bundle --release --universal   # → target/universal-apple-darwin/release/bundle/待办.app
```

`--release` 时包里的可执行文件默认去掉符号和调试信息，小很多（Linux 上 125 MB → 19 MB），要带符号时加 `--keep-symbols`。

## GPU：省电、高性能、没有 GPU 的机器

默认用省电的 GPU：双显卡的笔记本上是集成显卡，不会因为打开一个界面应用就唤醒独立显卡、多耗电。界面应用用它足够快。大量 3D、很重的自定义着色器时要独立显卡：

```rust
/// 默认省电：双显卡的机器上用集成显卡。大量 3D、很重的自定义着色器时要独立显卡
pub fn main() {
    App::new(|| text("3D 场景")).gpu(GpuPreference::HighPerformance).run();
}
```

偏好的 GPU 用不了时依次退到：另一种显卡 → 软件渲染（Windows 的 WARP、Linux 的 lavapipe，远程桌面、虚拟机里常见） → GL 上的显卡和软件渲染。软件渲染能画出一样的画面，只是慢，大窗口通常跑不满 120 帧。只有 GL 驱动能用的老显卡，用 `WGPU_BACKEND=gl` 只开 GL。

- 都用不了时不会崩溃：记一条错误说明原因（试过哪些 GPU、各自为什么不行），双击打开的应用在 macOS、Windows 上弹出提示框，然后以退出码 1 结束。
- 用户排查驱动问题：环境变量 `AUREOLE_GPU=software`（只用软件渲染）、`high-performance`、`low-power` 优先于代码里的设置。macOS 没有软件渲染的适配器。
- 选中的 GPU：`aureole::performance::gpu_info()`。
- GPU 设备丢失（驱动更新、显卡重置、外接显卡被拔掉）时自动重新创建一次，窗口接着画；再丢失时说明原因后退出。
- Windows 的 CI 运行器没有 GPU，用的就是 WARP：离屏截图、像素测试照样能跑（框架自己的 CI 就这样跑渲染器的像素测试）。

## 平台支持

各平台支持到什么程度见 [README 的平台表](../../README.md#平台支持)。

公开 API 不带平台条件：不支持的功能在其他平台上照样能调用，只是没有效果，代码里不用写 `#[cfg]`。Windows、Linux 的系统集成写好了、交叉检查过，还没在真的桌面里运行过。

Windows、Linux 上应用要自己准备的：

- **Windows**：通知要应用标识。安装程序在开始菜单建快捷方式，把快捷方式的 `System.AppUserModel.ID` 设成包标识符（比如 `com.example.todo`），从这个快捷方式启动时就能发通知；也可以打成 MSIX 包。
- **Linux**：装一个 `.desktop` 文件（`~/.local/share/applications/com.example.todo.desktop`，写上 `Name`、`Exec`、`Icon`），桌面才知道应用名和图标。文件对话框和外观设置要桌面装了 xdg-desktop-portal（GNOME、KDE 默认有）。
- **协议和文档类型**：系统要知道哪个程序处理它们，安装程序来写。`cargo bundle` 按 `url-schemes`、`document-types` 生成要写的东西（放进输出目录，`--exe` 指定安装后可执行文件的路径）：

```bash
cargo bundle --emit windows-reg --exe 'C:\Program Files\待办\todo.exe'  # 当前用户的注册表项（.reg）
cargo bundle --emit linux-desktop --exe /opt/todo/todo                   # .desktop：Exec=… %U，MimeType=x-scheme-handler/todo;…
cargo bundle --emit linux-mime                                           # 自定义文档类型的 MIME 声明
```

  - Windows：协议写在 `HKCU\Software\Classes\<协议>`（`URL Protocol`、`shell\open\command` 是 `"程序.exe" "%1"`），每种文档一个 ProgID，扩展名的 `OpenWithProgids` 里登记它；只有应用自己的类型才设成扩展名的默认值。用 `reg import 文件.reg` 或安装程序导入。
  - Linux：`.desktop` 装进 `~/.local/share/applications/` 后运行 `update-desktop-database ~/.local/share/applications`；MIME 声明装进 `~/.local/share/mime/packages/` 后运行 `update-mime-database ~/.local/share/mime`。默认处理程序用 `xdg-mime default 包标识符.desktop x-scheme-handler/todo` 设。

`cargo bundle` 以后会生成更多（Windows 的快捷方式、Linux 的图标），现在要自己做。

Windows、Linux 的编译检查（目标已经写在框架的 `rust-toolchain.toml` 里；在自己的项目里要先 `rustup target add x86_64-pc-windows-msvc x86_64-unknown-linux-gnu`）：

```bash
cargo check --workspace --all-targets --target x86_64-pc-windows-msvc
cargo check --workspace --all-targets --target x86_64-unknown-linux-gnu
```

Linux 上的系统库（X11、Wayland、xkbcommon、Vulkan、fontconfig）都在运行时加载，编译不需要开发包。
