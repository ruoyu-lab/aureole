# 26. 插件和扩展点

框架留了几个扩展点，让库和应用不用改框架就能接进来：

| 接口 | 用途 | 谁实现 |
|---|---|---|
| `Plugin` | 往应用上挂钩子、换执行器、改设置 | 第三方；框架自己的热加载 `HotReloadPlugin`、tokio 接入 `TokioPlugin` 也是 |
| `Spawner` | `spawn`、`spawn_blocking`、`resource` 的请求交给谁跑 | 框架的 `PoolSpawner`（默认）、`TokioSpawner`；别的运行时由第三方实现 |
| `MainThreadSender` | 别的线程把工作投到主线程 | 框架提供，拿来用 |
| `Cancel`、`CancelGuard` | 能取消的登记收成守卫，跟着一个值走 | 框架的定时器、任务、快捷键、文件监视；第三方的登记实现 `Cancel` 就能用 |
| `ElementKind` 和三个能力接口 | 自己定义元素 | 第 [25](25-自定义元素.md) 章 |
| `Element::builtin_handlers` | 自己做的控件的行为，排在使用的人的处理器之后 | 第 [14](14-基础控件.md) 章 |
| `aureole::host` | 把界面接到自己的窗口、事件循环、渲染器上 | 第三方；框架的真实窗口和测试工具也是这样接的，步骤和例子在模块说明里 |

本章的导入：

```rust
use std::cell::Cell;
use std::sync::Arc;
use std::sync::atomic::{AtomicUsize, Ordering};

use aureole::prelude::*;
use aureole::{BlockingJob, Cancel, CancelGuard, PlatformEventKind, Plugin, PoolSpawner, SendFuture, Spawner, Timer};
```

## 插件

`Plugin` 只有一个方法：拿到 `App`，返回装好的 `App`。和直接链式调用一样，不用另学一套：

```rust
/// 插件就是一个实现了 `Plugin` 的类型：拿到 `App`，挂钩子、换执行器、改设置，再还回去
struct FrameLog;

impl Plugin for FrameLog {
    fn build(&self, app: App) -> App {
        let frames = std::rc::Rc::new(Cell::new(0u64));
        let count = frames.clone();
        app.on_window_open(|window| println!("窗口建好了：{:?}", window.size()))
            .on_frame_end(move |frame| {
                count.set(count.get() + 1);
                if let Some(stats) = &frame.stats
                    && stats.laid_out
                {
                    println!("这一帧布局了，花了 {:?}", stats.layout_time);
                }
            })
            .on_exit(move || println!("一共 {} 帧", frames.get()))
    }
}
```

`App::plugin` 装，闭包 `|app: App| ..` 也是插件。`App::run` 开始时按顺序装，装的时候还能再装别的插件：

```rust
/// 装插件：`App::plugin`，也可以直接给一个闭包。`App::run` 开始时按顺序装，装的时候还能再装
pub fn with_plugins() {
    App::new(|| text("有插件的应用"))
        .plugin(FrameLog)
        .plugin(|app: App| app.title("闭包也是插件"))
        .plugin(|app: App| {
            // 窗口系统的事件换算成输入事件之前：吃掉键盘，元素树收不到（比如嵌在窗口里的原生视图拿走了键盘）
            app.on_platform_event(|event| {
                if event.kind() == PlatformEventKind::Keyboard && NATIVE_VIEW_FOCUSED.with(Cell::get) {
                    event.stop_propagation();
                }
            })
        })
        .run();
}

thread_local! {
    static NATIVE_VIEW_FOCUSED: Cell<bool> = const { Cell::new(false) };
}
```

| 钩子 | 什么时候 | 能做什么 |
|---|---|---|
| `App::on_window_open(\|窗口\| ..)` | 窗口建好以后（根视图挂好、渲染线程开始了） | 拿到 `WindowHandle`，代码在这个窗口里执行 |
| `App::on_platform_event(\|事件\| ..)` | 窗口系统的事件换算成输入事件之前 | `event.kind()` 看大类（`PlatformEventKind::Keyboard`……），`event.stop_propagation()` 吃掉，元素树收不到。窗口自己的处理照常（改大小、挪位置） |
| `App::on_frame_start(\|帧\| ..)`、`App::on_frame_end(\|帧\| ..)` | 每个窗口每帧推进前后 | `FrameInfo`：哪个窗口、帧的时间；结束的钩子里有 `stats`（这一帧布局了没有、花了多久） |
| `App::on_exit(\|\| ..)` | 应用退出前 | 收尾 |

- 钩子都在主线程上；后台的事经主线程投递回来（下面）。
- 插件的钩子只在真实窗口里调用，测试工具没有插件：插件里的逻辑写成普通函数，在测试里直接调用。
- 窗口库的类型不进公开接口：`PlatformEvent` 给大类和 `Any` 的原始事件，要细节的插件自己依赖同一版窗口库。

`cargo run -p aureole --example plugins` 在真实窗口里把这些都走一遍，退出时打印每个钩子被调用的次数。框架自带的两个：

- `aureole::devtools::HotReloadPlugin`：图片监视和重新编译后原地重启（第 [21](21-开发工具.md) 章）；
- `aureole::TokioPlugin`（`tokio` 特性）：把执行器换成 tokio（第 [16](16-异步任务与数据资源.md) 章）。

## 换执行器：`Spawner`

默认的 `PoolSpawner` 是框架自己的线程池：没有任务时没有线程在工作，但没有 IO 反应器和计时器，依赖 tokio 这类运行时的库在它上面跑不起来。要换就实现 `Spawner`，或者用 `tokio` 特性现成的 `TokioSpawner`：

```rust
/// 换执行器：`spawn`、`spawn_blocking`、`resource` 的请求都交给它。这里数一数，再转给内置的线程池；
/// 接别的运行时就是把 future 交给它。框架交来的 future 已经包好了（接住 panic、检查取消、交回结果），只管轮询到完成
#[derive(Default)]
struct Counting {
    spawned: Arc<AtomicUsize>,
}

impl Spawner for Counting {
    fn spawn(&self, future: SendFuture) {
        self.spawned.fetch_add(1, Ordering::Relaxed);
        PoolSpawner.spawn(future);
    }

    fn spawn_blocking(&self, job: BlockingJob) {
        self.spawned.fetch_add(1, Ordering::Relaxed);
        PoolSpawner.spawn_blocking(job);
    }
}

/// 应用用 `App::spawner` 换（测试和别的线程用 `set_spawner`）
pub fn with_spawner() {
    App::new(|| text("换了执行器")).spawner(Counting::default()).run();
}
```

- 交来的 future 已经包好：接住 panic、检查取消、把结果交回主线程。执行器只管轮询到完成，不用实现取消（取消就是唤醒 future，下一次轮询看到标记就结束）。没轮询完就丢掉时按 panic 交回，等它的一方不会一直等。
- **执行器按线程记**：`App::spawner` 给主线程换，`aureole::set_spawner` 换当前线程的（测试用）；后台任务里再发出的任务交给发出它的线程的那一个。`aureole::spawner()` 取出正在用的。
- 主线程执行器（`spawn_local`）、定时器不在接口里，仍归框架：它们和作用域、当前窗口、虚拟时间是一体的。

## 从别的线程回到主线程：`MainThreadSender`

`aureole::main_thread_sender()` 在主线程上拿到一个句柄，能带到任何线程，`send(闭包)` 把闭包投到主线程，按投递的顺序执行（第三方库的回调、原生线程、自己开的线程）：

```rust
/// 别的线程把闭包投到主线程：第三方库的回调、原生线程、自己开的线程。闭包要 `Send`，带不进信号：
/// 主线程上开一个任务等通道，结果到了再写信号
pub fn post_from_thread() -> Element {
    let status = signal(String::from("等结果"));
    let sender = aureole::main_thread_sender();
    let (tx, rx) = std::sync::mpsc::channel::<String>();
    std::thread::spawn(move || {
        let text = String::from("线程算好了"); // 真实应用里是第三方库的回调
        sender.send(move || {
            let _ = tx.send(text); // 这里已经在主线程上
        });
    });
    aureole::every(ms(50), move || {
        if let Ok(text) = rx.try_recv() {
            status.set(text);
        }
    });
    text(move || status.get()).name("status")
}
```

- 闭包要 `Send`，所以**带不进信号**：闭包里写线程局部的状态、发通道；要改界面就让主线程等通道（上面用定时器轮询；`spawn_local` 里等一个异步通道更好）。能用 `aureole::spawn(..).then(..)` 时不用它，那样结果直接交到主线程的闭包里。
- 从空变成非空时叫醒事件循环一次，主线程一次取走全部，在批量更新里执行；投递的工作不在任何作用域和窗口里。
- 接收方的线程退出后 `send` 返回 `false`。
- 测试工具里投递的工作在下一帧开始时执行。

## 守卫：`Cancel` 和 `.guard()`

定时器、任务、快捷键这些登记**归创建时的作用域**：作用域释放（元素卸载、窗口关闭、副作用重新执行）时取消，**丢掉句柄不会取消**。所以界面代码里写 `aureole::after(d, f);` 就行。

不在作用域里的代码（库自己的结构体、插件、`main` 里）没有人替它取消。这时用 `.guard()` 收成 `CancelGuard`，守卫丢掉时取消：

```rust
/// 库自己的结构体：定时器跟着它走，结构体丢掉时取消。不用守卫时定时器归创建时的作用域，
/// 不在作用域里创建的（`main` 里、插件里）就没有人取消它
pub struct Autosave {
    _timer: CancelGuard<Timer>,
}

impl Autosave {
    pub fn new(save: impl Fn() + 'static) -> Self {
        Self { _timer: aureole::every(secs(30), save).guard() }
    }
}
```

`Timer`、`Task`、`LocalTask`、`Shortcut`、`KeyUpListener` 和开发工具的文件监视都实现了 `Cancel`。守卫能借出里面的句柄查状态（`Deref`），`into_inner()` 取回句柄、不再当守卫，`cancel()` 马上取消。第三方的登记实现 `Cancel` 就能用：

```rust
/// 第三方的登记也能用守卫：实现 `Cancel`（`cancel` 必须拿走 `self`）
struct Subscription {
    id: u64,
}

impl Cancel for Subscription {
    fn cancel(self) {
        println!("退订 {}", self.id);
    }
}

fn subscribe() -> CancelGuard<Subscription> {
    Subscription { id: 7 }.guard()
}
```

## 坑

- **`.guard()` 的返回值要留着**：`let _ = every(..).guard();` 当场就取消了（`#[must_use]` 会提醒），放进变量或结构体的字段。
- 插件的钩子闭包是 `'static`，捕获状态用 `Rc<Cell<..>>` 这样的共享，`Plugin::build` 收的是 `&self`。
- `on_frame_end` 每个窗口每帧都调用，里面不要做重活；画面静止时不出帧，钩子也不调用，别拿它当定时器。
- `on_platform_event` 吃掉事件以后，换算的状态（修饰键、指针位置）不更新：吃掉按下却放过松开时，状态会对不上，成对处理。
- 换执行器只影响之后发出的任务，已经在跑的不挪。
